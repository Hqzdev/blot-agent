# Карта модулей Blot: кто за что отвечает

Версия: 1 ноября 2026. Основание: [полное ТЗ](../product/blot-technical-specification.md), [план](../product/blot-product-plan.md), матрица приёмки BLOT-01…30 из ТЗ. Размеры в строках — оценка (±40%), а не задание: число строк не критерий качества.

Документ для владельца проекта. Владелец проектирует и принимает, ИИ пишет код. Каждый блок ниже можно отдавать ИИ как отдельную задачу: у него есть границы, контракт, зависимости и приёмка.

Разделение на слои Gradle (`api → application → core`, `infrastructure` реализует порты) описано в [java-modules.md](java-modules.md) и остаётся в силе. Эта карта идёт поперёк слоёв: один блок обычно состоит из кода во всех четырёх. Отдельный облачный сервис из ТЗ от 1 ноября заменяет формулировку октября «облачный сервер не нужен».

## Как отдавать блок ИИ

1. Даёшь три вещи: раздел этого документа, нужные места ТЗ, строки приёмки BLOT-xx.
2. Просишь сначала тесты по приёмке, потом код.
3. Блок готов, когда проходят его сценарии на реальных данных и устройствах. Сборка и fixtures подтверждают компонент, но не закрывают строку матрицы.
4. Не начинай блок, пока не заморожены контракты, от которых он зависит (блоки 1 и 3).
5. Один блок — одна задача. Не проси ИИ «написать всё ядро».

## Четыре процесса

| Процесс | Что это | Где работает |
| --- | --- | --- |
| Клиент | SwiftUI (Mac, iPhone), Android Views, JavaFX (Windows) | устройство пользователя |
| Локальное ядро | Java 25, Spring Boot, SQLite | ПК: Mac или Windows |
| Облачный сервис | Java, Spring Boot, PostgreSQL | наш сервер |
| Расширение Chrome | Manifest V3, TypeScript | браузер на ПК |

```text
Клиент Mac/Windows ── локальный API ── ядро ПК ── адаптеры ОС, VM/WSL, Chrome
iPhone/Android ── relay (облако) ── защищённый канал ── ядро выбранного ПК
Любой клиент ── облако ── аккаунты, квоты, relay, шлюз GigaChat
```

Главное правило: клиент показывает и просит, решает ядро. Облако хранит только аккаунты и служебные данные, истории чатов и файлов у него нет, задачи оно не исполняет.

## Локальное ядро: 16 блоков

Блоки 1–5 образуют основу. Остальные опираются на них.

### 1. Домен и контракты (~1,5k)
- Отвечает: сущности `Device`, `TrustedPair`, `Workspace`, `AgentProfile`, `AgentConfigurationRevision`, `Conversation`, `Message`, `Task`, `TaskAttempt`, `Assignment`, `AgentSession`, `AgentMessage`, `PreparedAction`, `ApprovalGrant`, `ToolInvocation`, `Artifact`, `MemoryEntry`, `ContextSummary`, `Connection`, `McpConnection`, `Automation`, `AutomationRun`, `BudgetLedger`, `SyncCursor`. Состояния задачи: `DRAFT`, `PLANNING`, `WAITING_APPROVAL`, `QUEUED`, `RUNNING`, `WAITING_USER`, `PAUSED`, `COMPLETED`, `FAILED`, `CANCELED`, `INTERRUPTED`, у действия инструмента ещё `UNKNOWN`. Схемы OpenAPI и JSON Schema, общие для всех клиентов.
- Не отвечает: хранение, HTTP, Spring, SQL. Домен от них не зависит.
- Правила: у каждой изменяемой записи ID, владелец, workspace, версия, время. У работы дополнительно `executorDeviceId`, `originDeviceId`, task ID, revision. Секреты не попадают в DTO списков и события.
- Зависит от: ничего.
- Приёмка: основа для всех; BLOT-28 (`UNKNOWN`).
- Подробно: [сущности, состояния и расхождения с кодом](domain-model.md).

### 2. Хранение и синхронизация (~3,0k)
- Роли ТЗ: `SyncService`, `ArtifactStore`.
- Отвечает: SQLite WAL; миграции с резервной копией; данные, квитанция и outbox в одной транзакции; snapshot и события после курсора; tombstones; артефакты с хешем; шифрованный экспорт и восстановление; локальные FTS-индексы.
- Не отвечает: решения о выполнении; сеть; шифрование канала.
- Зависит от: 1.
- Приёмка: BLOT-07, 09, 28, 29.

### 3. Локальный API (~2,8k)
- Отвечает: HTTP и SSE; группы маршрутов `devices`, `conversations`, `agents`, `tasks`, `approvals`, `connections`, `mcp`, `automations`, `data` (группа `identity` живёт в облаке). Команда несёт `commandId`, тип, payload, ожидаемую версию, срок. Квитанция принятия отличается от результата. Десять доставок одного `commandId` дают одну операцию.
- Не отвечает: бизнес-логика. Контроллеры только проверяют данные и вызывают сценарии.
- Правило: владелец и тип устройства берутся из ключа, а не из JSON запроса.
- Зависит от: 1, 2.
- Приёмка: BLOT-06, 28.

### 4. Устройства и связь с телефоном (~2,2k)
- Роль ТЗ: `DeviceTrustService`.
- Отвечает: одноразовый QR с коротким сроком, подтверждение на ПК, код сверки, ключи устройств, отзыв, повторное сопряжение, шифрованный канал через relay (готовая криптобиблиотека, pinning ключей), sequence и срок команд, исходящая очередь, правило «ПК не создаёт работу на другом ПК» (проверяется на сервере).
- Не отвечает: сам relay (облако); содержимое задач.
- Зависит от: 1, 2, 3; облачный relay.
- Приёмка: BLOT-04, 05, 06, 07, 17, 28.

### 5. Модели и чаты (~4,0k)
- Роли ТЗ: `ConversationService`, `ModelRouter`, `BudgetService`.
- Отвечает: сообщения и их состояния (сохранено на телефоне → доставлено ПК → принято → выполняется → завершено); поток ответа; вложения (25 MiB, прогресс, отмена); `ModelProvider` и `ProviderCapabilities`; GigaChat через шлюз; личные ключи OpenAI, Anthropic, Gemini, xAI и совместимый API; бюджет (резерв до запроса, фактический usage, неизвестное отдельно); очередь и отмена; повтор только при временных ошибках.
- Не отвечает: решения агентов; хранение ключей (блок 15).
- Зависит от: 1, 2, 3, 15; облачный шлюз.
- Приёмка: BLOT-02, 25, 26.

### 6. Агенты и оркестрация (~5,0k)
- Роли ТЗ: `AgentDirectory`, `TaskPlanner`, `WorkflowScheduler`, `DelegationService`.
- Отвечает: CEO и постоянные агенты (имя, инструкции, модель, память, права); роли инженерной команды как конфигурации (Product Lead, PM, Tech Lead, Design Lead, Researcher, Backend, Frontend, Reviewer, QA, Security, Integrator); план с критериями и зависимостями; назначения; Motes (глубина 2, до четырёх одновременно, общий бюджет); сообщения между агентами; независимое ревью (автор не принимает своё изменение); итог CEO; жизненный цикл задачи, пауза, остановка, восстановление после перезапуска.
- Не отвечает: сами инструменты (блоки 8–12); решения о правах (блок 7).
- Правила: переходы ведёт детерминированный оркестратор, а не модель; права детей не шире родительских; активная сессия работает со снимком конфигурации.
- Зависит от: 1, 2, 5, 7.
- Приёмка: BLOT-08, 09, 10.

### 7. Разрешения и реестр инструментов (~1,8k)
- Роли ТЗ: `PermissionService`, `ToolRegistry`.
- Отвечает: режимы «наблюдение», «подтверждение», «доверенная область»; `PreparedAction` с точными параметрами; карточка подтверждения (действие, ресурс, компьютер, отправитель, diff, последствия, срок); «Да», «Нет», «Да, не спрашивай больше» (создаёт видимое правило); отзыв правил; инвалидация при смене получателя, содержимого, файла, Git HEAD, remote, ветки; список действий с обязательным отдельным подтверждением (push, значимое удаление, отправка, внешняя запись, приглашение, деплой); реестр инструментов со схемами и scopes, вызов только через проверку.
- Не отвечает: само исполнение действий.
- Правило: текст из письма, страницы или файла — данные, а не команда владельца.
- Зависит от: 1, 2.
- Приёмка: BLOT-11, 12.

### 8. Файлы и документы (~2,5k)
- Отвечает: поиск, чтение, индексация выбранных папок, создание, правка, переименование, перенос, сравнение, подготовка удаления (корзина). Форматы: текст, Markdown, JSON/YAML/CSV, PDF, DOCX, XLSX, PNG/JPEG, OCR. Hash и версия источника, конфликт с правкой пользователя, защита от выхода из области через ссылки и архивы. Лимиты 25 MiB на вложение и 100 MiB на результат.
- Не отвечает: аудио и видео (вне основной поставки).
- Зависит от: 1, 2, 7, 15.
- Приёмка: BLOT-13.

### 9. Код, терминал, Git (~3,2k)
- Роли ТЗ: `ProcessGateway`, `FileGateway`.
- Отвечает: запуск программ (программа, аргументы, папка, окружение, лимит вывода, таймаут); отмена дерева процессов; stdout, stderr, exit code; Mac VM runner; Windows WSL2 runner; зависимости внутри рабочей среды; preview через аутентифицированный туннель; Git (ветки, worktree, diff, commit, push с отдельными разрешениями); PR и деплой как внешние действия; честная ошибка, если нет компилятора или SDK.
- Не отвечает: установка системных программ (запрещена).
- Зависит от: 1, 2, 7, 15.
- Приёмка: BLOT-14, 15, 21.

### 10. Мост с Chrome (~1,0k)
- Роль ТЗ: `BrowserGateway`.
- Отвечает: Native Messaging с разрешённым extension ID; выдача доступа к вкладке или домену; DOM-инструменты; снимки вкладки; журнал; передача управления человеку при CAPTCHA, 2FA и входе.
- Не отвечает: само расширение (отдельный процесс).
- Зависит от: 1, 7.
- Приёмка: BLOT-16, 17.

### 11. Интеграции (~4,0k)
- Отвечает: Gmail (API), Яндекс Почта (IMAP/SMTP), Google Calendar, Яндекс Календарь (CalDAV), Telegram (Bot API), Slack, Notion, GitHub. Подключение с владельцем, workspace, аккаунтом, scopes, состоянием; несколько аккаунтов одного сервиса; OAuth с PKCE во внешнем браузере; проверка, переподключение, отзыв. Цикл письма: найти → открыть → черновик → показать → разрешение → отправить → внешний ID. Неизвестный исход отправки не повторяется вслепую. Входящие из Telegram и Slack принимаются только от привязанных отправителей.
- Не отвечает: решение о значимых действиях (блок 7).
- Зависит от: 1, 2, 7, 15.
- Приёмка: BLOT-18, 19, 20, 21.

### 12. MCP-клиент (~1,2k)
- Отвечает: stdio и Streamable HTTP; согласование версии протокола; discovery инструментов; показ пользователю; агент получает только разрешённое подмножество; смена схемы инструмента отзывает права; секреты в защищённых настройках; таймаут; известный и неизвестный исход.
- Не отвечает: изоляцию локального процесса. Сервер либо запускается в изолированной среде, либо добавляется как явно доверенный компонент.
- Зависит от: 1, 2, 7, 15.
- Приёмка: BLOT-27.

### 13. Расписания и автоматизации (~1,5k)
- Роль ТЗ: `AutomationService`.
- Отвечает: напоминание отличается от автоматизации; разовое время, повтор, дата окончания; timezone и перевод часов; триггеры (время, письмо, изменение сайта опросом, свободное время); политика пропусков (по умолчанию один объединённый запуск); уникальность запуска по паре «автоматизация + запланированное событие»; история; отметка «не доставлена», если ПК недоступен.
- Не отвечает: напоминания на телефоне. Их регистрирует операционная система телефона на стороне клиента.
- Зависит от: 1, 2, 6, 7, 11.
- Приёмка: BLOT-22, 23.

### 14. Память и сжатие контекста (~1,5k)
- Роль ТЗ: `MemoryService`.
- Отвечает: личная память, память агента, проекта, состояние задачи, история разговора; источник, дата, область, актуальность; «запомни» создаёт запись, автоматическое выделение даёт кандидата; локальный FTS-поиск; сжатие с порога 80% контекста до около 60%; резюме со ссылками на источники; правка или удаление источника отзывает резюме; просмотр, правка, удаление, запрет запоминания.
- Не отвечает: векторная БД (не нужна).
- Зависит от: 1, 2, 5.
- Приёмка: BLOT-24.

### 15. Адаптеры Mac и Windows (~1,5k)
- Отвечает: хранение секретов (Keychain и защищённое хранилище Windows), пути, процессы, уведомления, автозапуск, фоновая работа, выбор runner.
- Не отвечает: бизнес-логика.
- Зависит от: 1.
- Приёмка: BLOT-01, 29.

### 16. Диагностика и обновления (~0,8k)
- Отвечает: журналы с request ID, классом ошибки, длительностью и usage, без текстов писем, промптов и ключей; экспорт диагностики без секретов; проверка версии; миграция с резервной копией.
- Зависит от: 1, 2.
- Приёмка: BLOT-29.

## Клиенты

Общее правило: клиент не принимает решений о правах и исполнении. Протокол общий (OpenAPI, JSON Schema, одни и те же fixtures), код интерфейса у каждой платформы свой. Состояния и тексты ошибок одинаковые на всех платформах, см. `screens/states.png` и `screens/platforms.png`.

| Клиент | Что внутри | Размер |
| --- | --- | --- |
| Mac и iPhone (SwiftUI) | Экраны по макетам, модели представления, клиент API, очередь исходящих и локальная база на iPhone, QR, push, Keychain, встраивание Java-ядра и VM, DMG | 22–34k |
| Android (Java, Views) | Те же экраны, ViewModel и Room, клиент relay и шифрование, FCM, точные будильники для напоминаний, камера для QR, APK | 14–22k |
| Windows (JavaFX) | Компоненты общего дизайна, окно настроек, хранилище секретов, интерфейс раннера WSL2, jpackage-установщик | 12–20k |

Чему клиент отвечает сам: язык RU/EN, тема, питомец и его состояния, доступность, напоминания телефона без работающего ПК. Приёмка: BLOT-01, 22, 30.

## Облачный сервис (~9–15k)

- Аккаунты: регистрация, код на почту, восстановление пароля, сессии, отзыв, вход через Google, Apple, Яндекс. Вход не выдаёт доступ к Gmail и календарю.
- Relay: пересылает зашифрованные пакеты между устройствами, содержимое не видит, офлайн-очереди текстов не держит.
- Шлюз моделей: общий ключ GigaChat только на сервере, квоты, справедливая очередь, промпты и ответы не записываются в журналы.
- PostgreSQL: учётные записи, публичные ключи устройств, сессии, квоты, push-токены, минимум событий подключения.
- Приёмка: BLOT-02, 03, 05.

## Расширение Chrome (~5–9k)

Manifest V3, TypeScript, Native Messaging. Читает и действует только в выданных вкладках и доменах, не передаёт cookies в модель. Приёмка: BLOT-16, 17.

## Сквозные правила

Нарушение любого из них считается дефектом независимо от блока.

1. Любой побочный эффект идёт через `PermissionService`. Подтверждение действует только на ту операцию и область, для которой дано.
2. Отчёт «письмо отправлено», «сборка прошла», «запись создана» допустим только по подтверждённому результату инструмента.
3. Команда с одним `commandId` исполняется один раз.
4. Секреты не попадают в DTO, события, журналы, экспорт диагностики и промпты.
5. Один ПК не создаёт работу на другом. Проверка на сервере, не только скрытая кнопка.
6. Инструкции из писем, страниц и файлов — данные, не команды владельца.
7. Неизвестный исход внешнего действия не повторяется вслепую: сначала сверка или вопрос пользователю.
8. Ошибка объясняет причину (нет прав, лимит, нет SDK), а не изображает успех.
