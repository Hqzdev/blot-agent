# План разработки Blot для четырёх платформ

Дата: 1 ноября 2026. Целевой срок основной поставки: 1 декабря 2026. Часовой пояс плана: Asia/Yekaterinburg.

Blot — личный ИИ-помощник с постоянными агентами и командой исполнителей. Пользователь общается с CEO или отдельным агентом. Работа с браузером, почтой, файлами и кодом выполняется на выбранном компьютере. Телефон управляет этой работой через интернет и самостоятельно поддерживает обычный чат и простые напоминания.

Этот план и [полное техническое задание](blot-technical-specification.md) задают новый объём продукта. При расхождении с октябрьскими документами применяются эти требования. Старые отметки выполнения относятся к прежнему объёму и не подтверждают готовность новых возможностей.

## Решения по продукту

| Область | Решение |
| --- | --- |
| Название | Blot. Для текущего макета выбран персонаж Grok Bot с вариантами формы, цвета и движений; имена и роли Blot сохраняются отдельно |
| Платформы приёмки | macOS 27, iOS 27, Android 17, Windows 11 |
| Сайт | Лендинг, загрузки и документация. Браузерного клиента Blot нет |
| Компьютеры | Полное рабочее пространство; каждый исполняет только собственные задачи |
| Телефоны | Чаты, агенты, расписания, настройки; просмотр работы ПК и ответы на запросы разрешений |
| Несколько ПК | Отдельные рабочие пространства, привязанные задачи и подключения; без автоматического переноса исполнения |
| Удалённые команды | Телефон может управлять доверенным ПК. Один ПК не может поручать работу другому ПК |
| Модели | GigaChat из коробки через наш шлюз; личные API-ключи для остальных провайдеров |
| Хранение | История, память и файлы на устройствах; сервер хранит учётные записи и служебные метаданные |
| Дизайн | Общий стиль и поведение четырёх клиентов; все экраны и состояния проектируются в Pencil |
| Поздний этап | Голос, собственный браузер, управление интерфейсами сторонних приложений |

Платформы в таблице — обязательные среды проверки из ответов владельца, а не автоматическое изменение deployment target существующих приложений. До изменения сборочных настроек фиксируются модели устройств, архитектуры CPU и минимальные поддерживаемые версии. Начальная упаковка Windows рассчитана на x64; ARM64 требует отдельной сборки и приёмки.

## Предлагаемая архитектура

Локальный исполнитель — модульный Java backend, общий для Mac и Windows. Существующие `core`, `application`, `infrastructure`, `api` сохраняются. macOS и Windows получают разные адаптеры процессов, секретов, путей и уведомлений. Роль агента задаётся конфигурацией, а не подклассом.

| Компонент | Технология и назначение |
| --- | --- |
| Mac и iPhone | Swift, SwiftUI, существующие общие Swift packages |
| Android | Java, Android Views/XML, ViewModel и локальная SQLite через Room; без переноса Spring backend на телефон |
| Windows | JavaFX с собственными компонентами общего дизайна, Java; runtime включён в установщик |
| Локальное ядро ПК | Java 25, Spring Boot, SQLite WAL, локальные артефакты и журнал событий |
| Облачная часть | Один развёртываемый Java/Spring Boot сервис с модулями аккаунтов, relay и GigaChat gateway |
| Облачная БД | PostgreSQL для аккаунтов, устройств, сессий, квот и минимальных метаданных |
| Связь | HTTPS, REST, события SSE; relay передаёт зашифрованный канал устройств через WebSocket |
| Расширение Chrome | Manifest V3, TypeScript, Native Messaging, DOM-инструменты и обновляемые снимки вкладки |
| Интеграции | Адаптеры API, IMAP/SMTP, CalDAV и стандартный MCP в пределах возможностей сервисов |
| Лендинг | Существующий Next.js, React и каталог документации |

Выбор JavaFX для Windows позволяет сохранить Java и общий backend. Это проектное решение; внешний вид задаётся нашими компонентами. JavaFX не делает SwiftUI-код переносимым. Упаковка через `jpackage` включает runtime, а Windows-установщик собирается на Windows. Основания: [OpenJFX](https://openjfx.io/openjfx-docs/), [Oracle jpackage](https://docs.oracle.com/en/java/javase/25/jpackage/packaging-overview.html).

Необходимые серверные компоненты на старте: один Linux-хост с ориентиром 2–4 vCPU и 4–8 ГБ RAM, PostgreSQL, TLS reverse proxy, SMTP для аккаунтов и резервная копия служебной БД. Это начальная конфигурация для небольшой учебной группы, не измеренная пропускная способность. Инференс идёт во внешний API; GPU-сервер не нужен. Push использует APNs/FCM. Отдельные Kubernetes, Kafka, Redis и векторная БД для первого релиза не требуются.

Бесплатный тестовый API не означает бесплатный хостинг, домен, подпись и публикацию приложений. Для учебного показа допустим существующий сервер и тестовые способы установки; реальные ограничения дистрибуции показываются явно.

## Условия готовности

Учитель устанавливает клиент, создаёт аккаунт и получает ответ GigaChat без своего API-ключа. Подключает телефон к ПК, поручает CEO задачу, видит работу нескольких агентов и получает проверенный итог. Отдельно демонстрируются браузер, Gmail и Яндекс, напоминания без работающего ПК, разрешения, отказ в удалённом запуске ПК → другой ПК и восстановление после обрыва связи.

Подробные правила и приёмочные сценарии находятся в [полном ТЗ](blot-technical-specification.md). Подключение инструментов сторонних разработчиков описано в [руководстве MCP](integrations/mcp-developer-guide.md).
