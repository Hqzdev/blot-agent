# Свайп ответа и меню ПКМ

Проверено 3 ноября 2026 года.

- Жест трекпада: **два пальца вправо → сообщение движется влево → ответ**. Преобразование учитывает настройку естественной прокрутки macOS.
- Порог ответа — 64 pt. До порога жест можно отпустить или вернуть назад без ответа. После отпускания пузырь возвращается пружиной. При пересечении порога запрашивается тактильный отклик.
- Прокрутка блокируется только после фиксации горизонтального направления. Вертикальный жест не превращается в ответ, даже если позднее появляется горизонтальное движение. Инерция не запускает дополнительные ответы.
- Также поддерживается прямое перетаскивание пузыря мышью влево. При отмене жеста сдвиг сбрасывается.
- ПКМ и Control-click открывают ту же панель с шестью реакциями и действиями «Ответить», «Копировать», «Запомнить», что и удержание. Работает для исходящих и входящих сообщений.
- Один локальный монитор AppKit обслуживает только видимые области сообщений. Он снимается при удалении последней области; шапка и композер исключены из области маршрутизации.

Проверки:

- `scripts/verify-mac-reply-swipe.swift`: **23 проверки прошли**. Проверяются направление при обоих вариантах прокрутки, порог, отмена, возврат, осевая фиксация, дробные дельты и ограничение сдвига.
- `./script/build_and_run.sh --design`: код 0, без ошибок и предупреждений итоговой сборки.
- В приложении проверены сдвиг мышью с переходом в ответ, соответствующая цитата, ПКМ на собственном сообщении и сообщении агента, выбор ответа именно на выбранное сообщение. ПКМ на центральном профиле не открывает меню скрытых за шапкой сообщений.
- Инструмент UI-автоматизации отправляет обычную горизонтальную прокрутку без фаз трекпада; физический жест двумя пальцами отдельно не воспроизводился. Для него проверены преобразование направления и состояние жеста, а обработчик использует фазовые события `NSEvent`.
