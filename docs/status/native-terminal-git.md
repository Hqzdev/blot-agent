# Нативный терминал и Git Apple-ядра

Изменения в текущем проекте подключают выбранные папки, нативные команды и Git к чатам и очереди задач Mac. Телефон может выбрать проект доверенного Mac и отправить подписанное поручение.

## Выбранная модель исполнения

8 ноября 2026 владелец выбрал выполнение прямо на Mac и полный CLI для доверенных проектов. Основное приложение сохраняет App Sandbox. Встроенный `BlotWorkspaceExecutor.xpc` выполняется от текущего пользователя со своей конфигурацией доступа, без root, административной установки и login daemon. App Sandbox не выдаётся за изоляцию произвольного кода проекта: запущенные скрипты имеют доступ исполнителя и могут совершать внешние действия.

Клиент использует приватный bundled XPC service. На обеих сторонах задаётся code signing requirement фактического приложения/исполнителя; helper дополнительно проверяет UID. Отсутствие корректной подписи не включает обходной путь. Дочерние программы получают только stdin `/dev/null`, отдельные stdout/stderr и явно построенное окружение; прочие file descriptors закрываются при spawn. Закрытие XPC-соединения и выход из аккаунта останавливают исполнитель. Старый Java v2 VM runner остаётся отдельной реализацией; автоматического fallback к нему нет.

Настоящий sandboxed CLI host с ad hoc подписью на текущем физическом Mac прошёл приватное XPC-соединение, проверку подписи и запуск команды. Developer ID/release-distribution проверка не проводилась: система не предоставляет действующих signing identities. Документация Apple о [разделении возможностей helper](https://developer.apple.com/documentation/security/discovering-and-diagnosing-app-sandbox-violations) и [XPC services](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingXPCServices.html) описывает используемую границу.

## Проекты и интерфейс

На Mac проекты доступны из «Проект и терминал» над composer и из настроек подключений. Системный выбор папки создаёт bookmark. В настройке выбираются агенты, подтверждается доверие к коду и задаются классы заранее разрешённых операций. Пустой список доверенных классов оставляет подтверждение каждого изменения/команды. Выбор классов переводит выбранных агентов, кроме observe, в trusted scope; этот локальный проектный grant действует только для выбранных классов. Push подтверждается отдельно.

Файловый путь, bookmark, назначения, доверенные классы, переменные среды и Git credentials хранятся в account/device credential store. Существующий Project DTO получает `repositoryPath = device:<UUID>`; путь не реплицируется. Запись Project без локального binding не предоставляет прав. Удаление аккаунта очищает `native-projects:` credentials. Отзыв проекта останавливает его процессы и удаляет привязку; история задач/артефактов сохраняется.

Проект можно выбрать для текущего чата или явно для задачи. В задаче используется существующий `Task.projectId`; дочерняя задача наследует проект родителя. Исполнитель проверяет закреплённые инструменты родителей, текущие права агента, локальное назначение и состояние проекта/задачи. Телефон выбирает проект по устройству исполнения. Новый proof связывает projectId с поручением под доменом `BLOT-TASK-DELEGATION-2`. Прежние proof без проекта сохраняют прежний домен и формат; подмена проекта подпись не проходит. Публичные DTO/JSON Schema не изменены.

Mac показывает живые карточки процессов, команду, stdout/stderr, результат, остановку и diff. Подготовленный Git diff и точные параметры показываются в штатном окне подтверждения. iPhone получает сохранённые результаты, журналы-артефакты и состояния через существующую синхронизацию, а не прямой поток терминала. Подтверждения этого исполнителя выполняются на Mac.

## Команды и файлы

- Команда задаётся абсолютной программой, массивом аргументов, относительной рабочей папкой, выбранными именами настроенных переменных среды и таймаутом. Shell вызывается явно как `/bin/sh` или `/bin/zsh`; скрытого shell нет.
- Значения по умолчанию: 120 секунд, максимум 1800 секунд, четыре активных процесса в исполнительном контуре приложения, один процесс на проект/рабочую папку. Общий сохранённый stdout/stderr ограничен 1 MiB; данные сверх лимита дренируются, выставляется truncated. Чтение pipe и waitpid не блокируют cooperative pool Swift.
- Старт возвращает process ID и running; модель должна опрашивать статус. Завершение считается известным только после exit code, дочитывания pipe и сохранения invocation. Локальный журнал модели содержит последние 8000 символов каждого канала; полный ограниченный журнал сохраняется Artifact. Настроенные секреты и локальный корень заменяются перед показом/сохранением результатов.
- Пауза, отмена, отзыв и закрытие завершают process group и наблюдаемых потомков, включая перешедших в другую группу. PID проверяется вместе со временем рождения, чтобы не послать сигнал переиспользованному PID. Это управление жизненным циклом, а не защита от намеренного ухода доверенного кода из контроля процесса.
- Перезапуск не повторяет незавершённую команду. UNKNOWN блокирует новые изменения проекта до сверки. Завершённые вызовы возвращают сохранённый результат, в том числе после продолжения задачи; промежуточный running сверяется с фактическим журналом invocation.
- Структурированные файловые инструменты ограничены выбранным корнем и не разрешают `.git` или выход через symlink. Чтение UTF-8 — до 1 MiB с выдачей первых 48 000 байт и полного hash; запись — до 48 KiB с expected hash, координацией и атомарной заменой, сохранением POSIX permissions. Поиск — до 100 совпадений/10 000 просмотренных объектов, без скрытых и сборочных папок. Обычные CLI-команды не получают обещания этих файловых ограничений.

## Git

Фиксированные Git-операции реализованы в текущем Swift-контуре, без перенаправления в Java v2. Доступны status/diff/log, создание ветки на явном base, подготовка и выполнение точного commit/push. Main/master, платформенные `/main` и обнаруженная основная ветка защищены. Hooks, fsmonitor, внешние diff/filter программы и интерактивные credentials отключены. Force-push, stash/reset/rebase и автоматическое переключение checkout не добавлены.

Подготовка коммита фиксирует выбранные файлы, hash/permissions, HEAD, checkout, целевую ветку и tree. Пользовательские staged-изменения в выбранных файлах отклоняются; другие staged-изменения сохраняются. На текущей task-ветке применяется отдельный индекс и index lock; точный tree коммитится через commit-tree и compare-and-swap update-ref. Изменение входов отменяет подготовку. Сбой между обновлением ref и индекса считается неопределённым исходом и не повторяется вслепую.

Можно создать отдельную task-ветку на нужном base и передать её в подготовку коммита. Тогда checkout/HEAD и весь индекс пользователя остаются неизменными, а проверенные правки остаются доступны в текущей папке. Ветка, занятая другим worktree, отклоняется. Если целевая база уже отличается в выбранных файлах, действие требует адаптации вместо замены новых изменений старым содержимым.

Подготовка push фиксирует source branch, SHA, remote endpoint, destination и исходный checkout. Можно выбрать task-ветку без переключения checkout. Перед отправкой всё проверяется повторно, затем удалённая ссылка сверяется с SHA. UNKNOWN сохраняет binding в PreparedAction; «Проверить remote» может проверить его и после потери локального cache подготовки. Совпадение точного SHA подтверждает результат; несовпадение не считается доказанным отсутствием отправки. Пользователь может также явно сверить исход самостоятельно. Автоматического повторного push нет.

Отдельно настраиваются HTTPS Bearer credential с точным URL scope или сокет SSH agent. Они передаются только управляемым Git-командам, не обычному процессу. HTTP redirects отключены. Реальные внешние SSH/HTTPS remotes с личными credentials в этом блоке не проверялись. Полный CLI доверенного проекта остаётся более широкой возможностью: приложение не обещает запретить Git/сетевые действия внутри произвольного скрипта.

## Проверка

Финальная проверка 8 ноября 2026: 154 теста BlotWorkspace и 18 Apple integrations прошли; Java application/infrastructure — 44 теста в актуальном Gradle cache; schema validation — 167 фикстур. Настоящий XPC-прототип и три end-to-end сценария native service прошли, как и регрессии MCP (3), групп (10) и очереди задач (5). Debug-сборки Mac и generic physical-device iOS завершились успешно. После сборки с `CODE_SIGNING_ALLOWED=NO` Mac bundle подписан ad hoc повторно; `codesign --verify --deep --strict` прошёл. Свободное место оставалось выше 20 GiB.

- Полный BlotWorkspace suite: реальные процессы, каналы, таймаут, отмена, четыре процесса, отсутствующий toolchain, дочерний процесс в отдельной группе; файлы и CAS; Git freeze/stale inputs, staged changes и отдельная task-ветка; local bare remote, push и восстановление проверки ссылки; назначения, отказ/отзыв, pause, реплика и proof v1/v2.
- `scripts/check-native-xpc.sh`: sandboxed signed host → code requirement → настоящий bundled XPC → команда и каналы.
- `scripts/check-native-execution.sh`: реальные LocalWorkspaceService и XPC, детерминированная модель, временный Git-проект, штатный interaction center. Чат и затем project-bound queue task проходят read → write → command → poll/log → frozen diff → approved commit; посторонний staged-файл сохраняется. Проверяются повторное открытие и отзыв.
- Регрессии MCP, групп и задач; Apple integrations, Java application/infrastructure и 167 контрактных фикстур. Mac и generic physical-device iOS собираются без симуляторов.

Рабочие файлы и Git-операции проверок ограничены временными проектами; внешние Git-серверы и настоящая модель не используются. Скрипт подтверждает interaction center программно: ручная GUI-проверка и запуск на физическом iPhone остаются отдельной приёмкой. PTY, PR, deploy, Windows/Android и установка системных toolchain не входят в этот блок.

## Интеграция

Рабочий код применён в текущем `mac/workspace`. После проверок подготовлена локальная `mac/native-terminal-git` от актуального `origin/mac/main` (`f9f1ca7`). Ветка содержит этот отчёт и сфокусированный `docs/patches/native-terminal-git.patch`: база ещё не содержит предыдущих локальных Apple/MCP/queue блоков. Патч включает только эту задачу относительно исходной рабочей копии и рассчитан на интеграцию этих зависимостей; отдельно эта ветка не является собираемой реализацией. Проверена обратная применимость патча к текущей рабочей копии. Повторно применять его в текущем проекте не нужно. Push и PR не выполнялись.
