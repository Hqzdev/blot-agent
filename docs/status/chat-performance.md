# Производительность чатов Mac и iPhone

Изменения применены в текущей рабочей копии `mac/workspace`, поверх прежних Apple/MCP/terminal блоков. Работают для групповых и личных чатов. История, планы, результаты инструментов и пользовательские данные не удаляются; API, DTO, формат базы и синхронизация не изменены.

## Причины и исправления

- Каждая строка заново разбирала Markdown, искала упоминания и сканировала все ModelStep с декодированием request/tool JSON. Добавлены ограниченные кеши текста и результатов, индекс ModelStep по response ID и кеш регулярных выражений. Изменение содержимого, агентов, оформления и результатов отменяет соответствующий кеш. Планы, цитаты, вложения, реакции и закрепления используют индексы.
- Строки наблюдали общий snapshot и обновлялись при посторонних транзакциях инструментов. Отдельная `WorkspaceChatPresentation` публикует только изменившиеся входы чата. Короткие серии уведомлений объединяются в окно 80 мс. Неизменившиеся реакции/непрочитанные больше не пересобираются из-за ModelStep.
- SwiftUI получал всю историю сразу. Mac и iPhone начинают с последних 80 видимых сообщений; кнопка подгружает предыдущие 80. Переход по закреплению или ответу раскрывает нужный участок. Подгрузка не запускает анимацию всех старых сообщений и не отправляет пользователя вниз; новое сообщение сохраняет поведение следования за концом чата. Старый Mac-маршрут также использует окно истории.
- SQLite повторно декодировал неизменившиеся записи при каждой полной проекции. Кеш сверяет фактический payload, включая замену при прежней версии, rollback, tombstone и workspace. Запрос в БД и проверки доступа продолжают выполняться; решения о разрешениях не кешируются.
- Проверка состояния задачи на каждом фрагменте потока модели читала всю историю и журналы. Теперь она получает согласованную транзакционную проекцию только задач и invocations. Проверки исполнителя, предков, паузы, terminal и UNKNOWN сохранены.
- Mac повторял поиск приложения и получение его иконки для каждого значка плагина; теперь эти результаты кешируются. На iPhone подготовка snapshot виджетов вынесена с main actor, старый результат отменяется при новой публикации. Обновление только ModelStep больше не запускает публикацию виджетов.

Кеши имеют count/cost limits: записи 16 MiB, готовый текст 8 MiB, Markdown 4 MiB, атрибуция 4 MiB, планы 2 MiB, иконки Mac 8 MiB. Это лимиты стоимости NSCache, не обещание фиксированного общего RSS приложения. Ошибка или вытеснение кеша приводит к повторному вычислению, не потере данных.

## Проверка 8 ноября 2026

| Проверка на текущем физическом Mac | До / без кеша | После / с кешем |
| --- | --- | --- |
| 1000 записей × 8 чтений | 250 мс | 28 мс |
| 400 повторных запросов значка с журналом около 16 KB | 55,9 мс | 0,099 мс |
| 40 сообщений с Markdown/упоминаниями × 8 настоящих SwiftUI image renders | 494 мс | 420 мс |
| Строки при открытии истории в 10 000 сообщений | вся история в data source | 80 |

Это локальные микропроверки; сравнение отрисовки использует сохранённые исходники до задачи с одинаковыми текущими модулями ядра. Значения не являются измерением FPS, батареи или общей загрузки пользовательского чата. Основные проверки воспроизводятся `scripts/check-chat-performance.sh`; локальный `--baseline` использует исходники в `.build/chat-performance-baseline`.

Прошли 155 тестов BlotWorkspace, включая 1000 записей с проверкой числа декодирований, одинаковой версии/нового payload, rollback и удаления. Production presentation harness проверил 10 000 сообщений, подгрузку, раскрытие старого сообщения, обновление плана и плагина при прежней версии, сохранение inline code/links и отсутствие invalidation авторов/вложений/реакций при tool-only обновлении. Прошли регрессии MCP (3), групп (10), очереди задач (5), 167 schema fixtures и существующие Java application/infrastructure проверки (44 теста, Gradle up-to-date).

Debug-сборки Mac и generic physical-device iOS прошли. Симуляторы не запускались. Свободное место сохранялось выше 20 GiB, использованы прежние сборочные каталоги. Физический iPhone отображается offline: ручная прокрутка и Instruments на телефоне не проверены. Ручной замер пользовательского чата и FPS на Mac также не выполнялся; SwiftUI отрисовка проверялась изолированно на тестовых данных, без открытия личной базы.

## Интеграция

Для общей Apple-работы подготовлена одна локальная ветка `mac/chat-performance` от актуального `origin/mac/main`. База ещё не содержит предыдущие локальные зависимости; ветка содержит этот отчёт и `docs/patches/chat-performance.patch` относительно исходной рабочей копии. Код уже находится в текущем проекте, повторно применять патч здесь не нужно. Отдельно ветка с патчем не является собираемым приложением. Push и PR не выполнялись.

## Проверка работающего приложения в Xcode

Дополнительный sample во время ручной прокрутки пользователя: PID 1656, 20 секунд с интервалом 1 мс, без чтения accessibility tree во время записи. Footprint в конце 94,9 MiB, максимум за жизнь процесса 268,4 MiB; такой замер не доказывает утечку. Главный поток большую часть записи ожидал событий; во время прокрутки были обновления AttributeGraph/Core Animation и разрешение локализованного текста. Дополнительно выявлено повторное построение полного backup snapshot каждые 5 секунд в фоне; оптимизация этого канала в данную правку прокрутки не включена.

У текста с упоминаниями устранена вложенная интерполяция всего накопленного `Text` на каждом упоминании. Используется сбалансированная композиция нативных сегментов, сохраняя изображения, цвета и Markdown. На одинаковом тесте из 40 сообщений с 36 упоминаниями, 8 SwiftUI image renders, время изменилось с 2,618 до 1,203 секунды. Это локальное измерение layout, не обещание удвоенного FPS. Плоская интерполяция не показала улучшения и не вошла в итоговый код.

Композиция намеренно использует доступный, но deprecated с macOS/iOS 26 оператор `Text +`: интерполяция в данном цикле возвращает измеренную дорогую локализацию. Предупреждение сборки сохранено, приватных API и подавления diagnostics нет. Mac и generic physical-device iOS собираются; повторное измерение ручной прокрутки после этой последней правки не проводилось. Дополнительный `chat-scroll-text.patch` применяется после основного патча. Исходный Xcode-процесс был запущен из другого DerivedData со старой сборкой; при проверке важно сверять действительно запущенный бинарник.
