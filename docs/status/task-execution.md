# Локальное исполнение задач Apple-клиентов

Изменения применены в текущем проекте в `mac/workspace`. Схемы v3 и публичные DTO не изменены.

## Поведение

- `LocalWorkspaceService.load()` восстанавливает прерванные записи и запускает один локальный `WorkspaceTaskQueue`. Очередь наблюдает изменения репозитория; задачи одного чата ждут освобождения его исполнителя. Модель использует общий ограниченный пул.
- `WorkspaceTaskLifecycle` атомарно захватывает задачу, сохраняет её исходное сообщение, обновляет состояния Task/AgentSession/AutomationRun. Пауза и отмена не перезаписываются поздним завершением. Версия записи ограждает продолжение от старого исполнителя.
- `WorkspaceTaskExecution` выполняет закреплённую конфигурацию агента. Разрешённые функции дополнительно пересекаются с текущими разрешениями.
- Продолжение восстанавливает сохранённый запрос и результаты функций. Повтор уже успешной операции с теми же аргументами после продолжения получает сохранённый результат. Неизвестный или отсутствующий результат блокирует автоматический повтор; сверенный результат берётся из соответствующего PreparedAction/ToolInvocation.
- При повторном открытии безопасно прерванные задачи возвращаются в очередь; пауза сохраняется. Уже сохранённый окончательный ответ завершает задачу без новой генерации.
- Служебные задачи отдельных Apple-действий не запускаются как новые поручения. Учитываются также прежние queued-записи, имеющие подготовленное действие, но не имеющие собственного модельного исполнения.
- Команды start/pause/stop подключены к сервису и экрану задач Mac/iPhone. Остановка из чата также отменяет текущую локальную задачу.

## Совместимость

Новый флаг `runnable: false` используется только в локальной команде создания служебной задачи. Для обычного создания поле опускается, сохраняя прежний digest повторяемой команды. Передаваемые записи не получают новых полей. Идентификаторы подготовленных Apple-действий сохранены; общий расчёт вынесен в `WorkspaceToolCallIdentity`.

Резерв бюджета модели использует отдельный идентификатор `ModelBudget`: он не конфликтует с командой записи `ModelStep`. Резервы сохраняются между продолжениями; неизвестное фактическое использование не обнуляется.

## Проверки

- `swift test --package-path packages/BlotWorkspace`: жизненный цикл, единственный захват, отмена, пауза, продолжение без повторной записи, ограждение версии, перезапуск, неизвестные и сверенные результаты, служебные задачи, бюджет.
- `swift test --package-path packages/BlotAppleIntegrations`: совместимость инструментов и восстановление обнаруженных функций только для того же источника/агента/задачи.
- `./scripts/check-group-routing.sh`: существующие сценарии групп.
- `./scripts/check-group-routing.sh .build/xcode/Build/Products/Debug scripts/verify-task-execution.swift`: текущий сервис приложения с тестовой моделью и временной БД — создание, повтор команды, пауза, повторное открытие, продолжение, отмена, ожидание занятого чата.

Проверки не отправляют запросы настоящей модели и не изменяют данные системных приложений. Системный фоновый планировщик, удалённое исполнение, MCP и новые внешние интеграции относятся к отдельным блокам.
