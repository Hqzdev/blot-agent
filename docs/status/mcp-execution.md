# MCP в локальном Apple-ядре

Реализация в текущем проекте подключает внешние MCP-инструменты к чатам, группам и очереди задач Mac/iPhone. Java-исполнитель MCP этим изменением не добавляется.

## Подключение и доступ

Настройки → MCP позволяют проверить сервер, просмотреть инструменты и их входные схемы, выбрать инструменты и агентов, сохранить доступ, обновить discovery или отключить сервер. На Mac этот же экран встроен в основное окно настроек.

- Streamable HTTP поддерживает HTTPS и HTTP только на loopback для локального сервера. Bearer-токен вводится отдельно; URL с credentials, query и fragment отклоняется. Автоматические перенаправления отключены. Интерактивного OAuth flow в этом блоке нет: нужен выданный сервером токен либо сервер без авторизации.
- stdio доступен только на Mac: абсолютный путь к программе, JSON-массив аргументов, явная рабочая папка, JSON-объект переменных среды, timeout и подтверждение доверия программе. Shell не запускается, окружение Blot не наследуется. Системный выбор программы/папки сохраняет security-scoped bookmarks. Доступ исполняемой программы ограничен sandbox приложения; MCP не обещает отдельной изоляции процесса. Системные программы и зависимости автоматически не устанавливаются.
- Параметры, токены, bookmarks, обнаруженные схемы и назначения хранятся в устройственной Связке ключей. Рабочий сервис использует account credential store; удаление аккаунта удаляет его `mcp:` записи. DTO не получает секретов: существующий `McpConnection.endpoint` содержит `device:<UUID>`. Другое устройство видит имя и идентификаторы разрешённых инструментов, но не получает права выполнения.

## Протокол

Поддержанный профиль: **2025-11-25**, `initialize`, согласование tools capability, `notifications/initialized`, `tools/list` с пагинацией и `tools/call`. HTTP принимает JSON и SSE, сохраняет session ID, отправляет согласованную версию в заголовке. Серверные ping получают ответ; неподдержанные запросы клиента получают JSON-RPC Method not found. Инструкции сервера не становятся системными инструкциями агента. Реализация основана на официальных разделах [transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports), [lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle) и [tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools).

Это профиль инструментов: resources, prompts, sampling, elicitation, protocol tasks, автоматическое возобновление HTTP streams и новые версии протокола не заявляются. Ответы не повторяются автоматически при обрыве. Discovery обновляется вручную и проверяется в сессии вызова до и после пользовательского подтверждения.

Лимиты: до 30 подключений, до 100 инструментов и 20 страниц discovery на сервер; каталог одного сервера до 512 KiB, отдельное сообщение транспорта до 1 MiB, аргументы до 48 KiB, результат после исключения встроенных binary blocks до 56 KiB. Таймаут 1–300 секунд. Для JSON Schema локально проверяются основные типы, required, enum/const, локальные references, unions, свойства, массивы, границы и patterns; глубина/число проверок и время regex ограничены. Сервер также валидирует входную схему; полное соответствие всем JSON Schema vocabularies не заявляется.

## Выполнение и восстановление

Каждый MCP-вызов считается потенциальным внешним изменением независимо от server annotations. Выбор доступа делает инструмент доступным агенту, но не подтверждает вызовы. На каждый вызов пользователь видит сервер, программу/адрес, инструмент, устройство и точные аргументы. Явные ограничения «только чтение»/«не отправлять» консервативно блокируют MCP, поскольку класс операции не подтверждён доверенным адаптером.

Вызов проходит через существующие PreparedAction/ApprovalGrant/ToolInvocation. Проверяются устройство, локальное назначение, текущая конфигурация агента, выбранный инструмент, состояние задачи и конфликты. Схема и версия локальной конфигурации входят в стабильный ID инструмента; обновление discovery отзывает прежний доступ. Реплицированная запись сама не может выдать полномочия. После подтверждения проверки повторяются.

Успешный результат сохраняется до возвращения в модель. Повтор того же вызова с теми же аргументами получает сохранённый результат. Изменённые аргументы не наследуют согласие. Групповое продолжение также повторно использует завершённые MCP-операции. `isError` сохраняется как failed. Текст и structured JSON возвращаются как `untrusted_content`; binary blocks не включаются в контекст, а случайно отражённые значения credentials редактируются перед сохранением результата.

При потере ответа после начала вызова сохраняется UNKNOWN; новые вызовы этого подключения блокируются. После перезапуска существующее восстановление переводит незавершённые invocation в UNKNOWN. В настройках пользователь сверяет фактический результат на сервере и отмечает «выполнено»/«не выполнено». Это не повторяет вызов. Отключение закрывает активные транспорты, удаляет credentials подключения и отзывает инструменты агентов. При выходе из аккаунта транспорты останавливаются.

## Проверки

- Полный `BlotWorkspace` suite, включая MCP-сценарии разрешений, отказа, повторов, смены схемы, отзыва во время подтверждения, изоляции реплики, ошибок сервера и редактирования отражённых credentials.
- Независимый Python stdlib сервер на реальных loopback sockets: JSON/SSE, session/version/auth headers, пагинация, server ping, отказ авторизации, redirect без передачи credentials, неправильный request ID и превышение размера ответа.
- Настоящий stdio subprocess: handshake, discovery, вызов, отсутствие наследованного HOME, отмена и timeout молчащего сервера.
- `scripts/verify-mcp-execution.swift`: реальный LocalWorkspaceService, отдельный stdio-сервер и детерминированная модель. Проверяется чат → подтверждение через существующий interaction center → инструмент → сохранённый результат → ответ модели, затем выполнение через task queue, повторное открытие и отключение.
- Сборки Mac и generic physical-device iOS без запуска приложений и симуляторов; существующие Java и schema checks.

Скриптовое подтверждение interaction center проверяет интеграцию сервисов, но не заменяет ручное нажатие в GUI. Настоящий сторонний MCP-сервис, системная выдача доступа выбранному executable, Keychain в подписанном приложении и HTTP на физическом iPhone требуют отдельной пользовательской проверки. Личная почта, файлы и внешние аккаунты при автоматических проверках не используются.

Итог: **140 тестов BlotWorkspace и 18 тестов BlotAppleIntegrations прошли**. Java application/infrastructure checks успешны, Gradle использовал существующие up-to-date результаты 44 тестов. Проверка 167 контрактных фикстур прошла. Обе Apple-сборки успешны. Проверка сервиса MCP подтвердила три сценария выше; существующие проверки групп и жизненного цикла задач также прошли. Одноразовые executables/cache проверок удалены, переиспользуемые incremental-сборки сохранены; свободное место осталось выше 20 GiB.

## Ветка для ревью

Рабочий код применён и проверен в текущем проекте `mac/workspace`. На момент подготовки ветки `origin/mac/main` (`f9f1ca7`) ещё не содержит предшествующие локальные блоки Apple-интеграций, очереди задач и групп. Поэтому `mac/mcp` содержит этот отчёт и сфокусированный `docs/patches/mcp-execution.patch` с изменениями только этой задачи, без включения чужих незакоммиченных файлов. Патч рассчитан на состояние проекта с этими предшествующими блоками; он уже применён в текущем проекте, повторно применять его здесь не нужно. Ветка не является отдельной собранной версией приложения: после интеграции зависимостей патч нужно применить и проверить на целевой базе.
