# Настройка backend владельцем через .env

> **Статус: отчёт на октябрь 2026.** Показывает, что было сделано и проверено на ту дату. Текущие требования — в [ТЗ от 1 ноября 2026](../product/blot-technical-specification.md).

SMTP и общий доступ GigaChat задаются один раз для процесса backend. Все аккаунты этой установки используют заданные параметры автоматически. История, память, проекты и бюджеты по-прежнему разделены по аккаунтам.

## Заполнение

В корне репозитория есть `.env.example`. Создайте приватный файл:

```sh
cp .env.example .env
chmod 600 .env
```

Заполните `BLOT_SMTP_HOST`, `BLOT_SMTP_PORT`, `BLOT_SMTP_USERNAME`, `BLOT_SMTP_PASSWORD`, `BLOT_SMTP_FROM`. Поддерживаются порт 587 с обязательным STARTTLS и порт 465 с TLS. В зависимости от почтового сервиса нужен отдельный пароль приложения.

Для модели задайте `BLOT_GIGACHAT_AUTH_KEY` — готовый Authorization Key без `Basic`, `BLOT_GIGACHAT_MODEL` и лимиты. Лимит контекста должен соответствовать выбранной модели. Авторизация текущего адаптера использует `GIGACHAT_API_PERS`.

Если для API требуется дополнительный CA, укажите абсолютный путь в `BLOT_GIGACHAT_CA_FILE`. PEM выбирает и проверяет владелец. Он загружается только в отдельный HTTP-клиент GigaChat, без изменения доверия операционной системы.

Значения могут быть без кавычек или в одинарных/двойных кавычках. Многострочные значения и `${...}` не поддерживаются. `#` внутри значения сохраняется; комментарии размещаются отдельной строкой. Файл не исполняется как shell. Ошибки называют параметр или номер строки, без значения секрета.

## Запуск

```sh
scripts/run-backend.sh
```

Скрипт выбирает подготовленный JDK 25, передаёт путь через `BLOT_ENV_FILE` и запускает backend. Если `.env` существует в корне репозитория, обычный `backend/gradlew -p backend :api:bootRun` также подключает его.

Для уже собранного JAR на машине владельца:

```sh
BLOT_ENV_FILE=/absolute/path/to/.env java --enable-native-access=ALL-UNNAMED -jar backend/api/build/libs/blot-backend.jar
```

Приоритет: параметры JVM/Spring и переменные окружения процесса выше значений файла. Путь `BLOT_ENV_FILE` задаётся извне; он не читается из самого файла. После изменения конфигурации перезапустите backend. Не запускайте два сервера с одной базой.

При локальном запуске через `script/build_and_run.sh` launcher читает `.env` и передаёт его в stdin приложения через FIFO в приватном временном каталоге. Это обходит ограничение macOS, запрещающее launchd самостоятельно открывать файлы Desktop. Данные не записываются во временный файл; канал удаляется после передачи. Mac дочитывает поток до конца и передаёт содержимое Java по приватному pipe до запуска broker. Секреты не попадают в аргументы, журналы или ресурсы. App Sandbox остаётся включённым. Выбранный публичный CA копируется отдельно в `Backend/provider-ca.pem`; пароль и ключ API туда не записываются.

Перед повторным запуском завершите отладку Blot кнопкой Stop в Xcode. Скрипт обнаруживает остановленный или отлаживаемый процесс и сообщает об этом до сборки; обычный экземпляр приложения получает запрос завершения с ожиданием до пяти секунд.

Для этого локального режима Apple-сертификат не требуется: используется ad hoc без Hardened Runtime. Сборка с настоящей `BLOT_SIGNING_IDENTITY` включает Hardened Runtime. Обычная схема Xcode тоже упаковывает backend; для передачи локального `.env` запускайте через скрипт. Реальный запуск упакованного приложения остаётся отдельной проверкой.

## Поведение приложения

- Полностью заполненный SMTP используется сразу; форма настройки почты на экране входа скрыта.
- Общий ключ и настройки модели применяются к Work, планированию, специалистам и сжатию контекста. Пользователю не нужно сохранять настройки модели перед первым запросом.
- В Settings → Models вместо полей ключа и сертификата показывается подключённая модель.
- API отклоняет попытки заменить заданные владельцем SMTP, ключ, CA и настройки модели.
- `GET /v2/setup/status` сообщает только режим настройки и публичные лимиты модели. SMTP, ключи и пути к файлам не возвращаются.
- Если раздел не настроен через окружение, сохраняется прежний персональный режим с Keychain. Частично заполненный SMTP приводит к понятной ошибке запуска.
- Один общий ключ GigaChat обслуживается общей последовательной очередью. Бюджеты аккаунтов остаются отдельными; стоимость запросов списывается с общего внешнего доступа владельца.

## Граница локального приложения и общего сервиса

`.env` не является шифрованием или способом скрыть секрет от владельца машины. На вашем сервере его защищают права доступа и серверная граница. Если поместить общий пароль в DMG или загрузить его на Mac пользователя, пользователь сможет получить этот пароль.

Поэтому `.env` исключён из Git и не включается в JAR, `.app` или DMG. Упаковка останавливается, если внутри `.app` найден `.env`. Общие коммерческие секреты должны оставаться на вашей инфраструктуре.

Текущая архитектура Blot запускает backend локально на каждом Mac, а регистрация доступна только через локальный канал. Подключение всех распространяемых DMG к вашему общему сервису SMTP/модели требует отдельного серверного API и клиентских адаптеров; добавление `.env` само по себе этого не делает. Не публикуйте текущий локальный API в интернете как готовый общий сервис.
