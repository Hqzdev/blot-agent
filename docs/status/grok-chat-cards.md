Реализован общий блок карточек переписки Blot для macOS и iOS по референсам [S009–S019 Grok Bot](../research/grok-bot-complete/ui-blocks.md). Изменения находятся в текущем проекте; production-деплой не выполнялся.

| Карточка | Подключение к поведению |
| --- | --- |
| Email | Просмотр реального черновика Mail, редактирование получателей/темы/текста, повторная подготовка точных параметров, Send/Discard. Отправитель закреплён за выбранным аккаунтом; вложения проверяются в Mail. |
| Вопрос | `conversation_ask`, варианты/свой ответ, сохранённый ответ и блокировка повторной отправки. |
| Подписка | Переход на `/app/pricing?cardId=…`, проверка статуса через авторизованный сервер, привязка платежа к владельцу и карточке. |
| Команда | Подготовленное действие и его реальные параметры. Разрешить один раз, отклонить; для native process_run — правило на точную команду, агента и ревизию проекта на этом устройстве. Сброс правила в настройках проекта. |
| Ручной шаг | Приостановка действий агента в сессии встроенного браузера, Take over / Done / Skip. На iPhone браузер полноэкранный; возврат управления доступен внутри браузера. |
| Результат задачи | Реальное завершение задачи; файлы и ветка из успешных native-вызовов. PR появляется при подтверждённом JSON-результате `gh pr view --json url`; выдуманные ссылки не создаются. |
| Slack | Редактирование текста и отправка через настроенный Slack MCP. Адаптер для `slack_post_message`, `slack_send_message`, `chat_postMessage`, `chat.postMessage` с полями channel/text/thread_ts; нестандартные схемы сохраняют общий просмотр точных параметров MCP. |
| Приложение | `connection_status`, фактические состояния подключения, число инструментов, переход в настройки. Добавление не приравнивается к авторизации. |
| Защищённый ввод | `secure_input_request`; значение сохраняется в Keychain устройства выполнения. В истории и ответе инструмента только ссылка, привязанная к владельцу. Ключ не переносится обычной синхронизацией. |
| Cookies | Создание/выбор локальных профилей Blot; перенос только между зарегистрированными профилями и для подтверждённых доменов. Значения cookies не возвращаются инструменту и не записываются в переписку. |
| Ошибка Mail | Сохранённое представление черновика. Перед повтором пользователь сверяет фактический результат; новый вызов повторно показывает подтверждение и имеет устойчивый ID. |

Карточки хранятся транзакционно в SQLite. `ConversationCard` добавлен в исходный v3-контракт и сгенерированные Swift/Java DTO. При синхронизации карточки передаются в необязательном поле `conversationCards` снимка, отдельно от последовательности старых encrypted deltas. Старые клиенты продолжают читать обычные сообщения, игнорируя метаданные карточек. Исполнитель фиксирует принятый ответ перед продолжением операции; последующие ответы не переоткрывают выполнение. Вопрос обновляет текстовую историю от имени устройства-исполнителя, сохраняя существующую проверку авторства сообщений.

Нативные ответы также показывают блоки кода с копированием, заголовки и таблицы; inline Markdown, ссылки и атрибуция агентов/навыков сохраняются. Файлы, реакции, закрепления и текущая доставка сообщений продолжают использовать существующие компоненты.

Каталог цен общий: [contracts/subscription-plans.json](../../contracts/subscription-plans.json). Premium — 2 500 ₽, Super — 5 000 ₽, Ultra — 10 000 ₽ за месяц. Тестовые подписки хранятся отдельно от действующих; автоматического списания за следующий период нет. Старые Free/Team и история платежей сохраняются.

Для деплоя web-приложения нужны серверные переменные:

```dotenv
YOOKASSA_SHOP_ID=1282645
YOOKASSA_SECRET_KEY=<ключ из защищённого окружения>
YOOKASSA_VAT_CODE=1
```

Предоставленный ключ сохранён только в игнорируемом `apps/web/.env.local`; в примерах и diff его нет. Read-only запрос настроек ЮKassa подтвердил магазин и `test: true`, HTTP 200. Реальный платёж при этой проверке не создавался.

`pnpm build:cloud` применяет новую миграцию `0007_test_subscription_catalog`, проверяет тестовый магазин и цены в БД, затем выполняет существующую проверку чата и сборку. Переменные нужно добавить в deployment, который выполняет billing: по умолчанию это `apps/web` с пустым `BILLING_SERVICE_URL`. При отдельном billing-service ему также требуется актуальный код и эти переменные. Публичный `AUTH_URL` используется для возврата на `/app/payment/success`; существующие PostgreSQL/auth/proxy-настройки остаются необходимыми. URL уведомлений: `/app/api/yookassa-webhook`; статус дополнительно проверяется через API провайдера при запросе результата. Для обновления публичных цен/ссылок нужен также deployment `landing` по существующей схеме общего домена.

Проверки: macOS/iOS typecheck, компиляция Java DTO, 168 schema fixtures, нативный тест Markdown-блоков, TypeScript, 56 web unit-тестов и Biome для изменённых billing-файлов. Swift runtime-проверки карточек выполнены: 4 теста прошли, включая запись/ответ/повторное открытие SQLite для всех 11 типов, повторный ответ, истечение срока, запрет передачи секретов в ответе карточки, совместимость снимков и ответ с другого устройства.

17 ноября выполнены полная Debug-сборка BlotMac и запуск на физическом Mac через `./script/build_and_run.sh --verify`. Окно существующего аккаунта проверено через Accessibility и снимок экрана. Изолированный нативный NSHostingView отрисовал все 11 production-компонентов в обеих темах (22 кадра); просмотрены каждый светлый кадр и общий лист тёмных кадров. Образцы не подключаются к аккаунту и не отправляют сообщения. Четыре runtime-теста проверяют локальные переходы состояния и хранение, а не внешних провайдеров. Фактические отправки Mail/Slack, платёж, сохранение настоящего ключа и перенос настоящих cookies не выполнялись.

Свободное место восстановилось до 35 ГиБ. Физический iPhone 13 Pro Max найден, но попытка сборки на него завершилась тайм-аутом Xcode «Preparing iPhone». Затем пользователь выбрал «Сейчас проверить только Mac»; установку, запуск и визуальную проверку iPhone отложили. Подготовленный iPhone rendering-тест ещё не запускался. Симуляторы не использовались.

Текущая ветка — `mac/workspace`. `origin` обновлён. Перед отдельной веткой `mac/grok-chat-cards` остаётся согласовать основу: текущий HEAD содержит ранее закоммиченные workspace/tool/UI-изменения сверх `origin/mac/main`, а весь `apps/web` уже был untracked до этой задачи. Эти чужие незавершённые изменения не включались в коммит, не сбрасывались и не переносились. Для обзора отдельно сохранены patch этой задачи и baseline затронутых web-файлов в `.build/grok-chat-cards`.

Исправление 17 ноября 2026: в `WorkspaceConversationCards.swift` добавлен прямой импорт `BlotAppleIntegrations`, необходимый для вызовов браузера. Предыдущая ручная проверка типов не включала проектный флаг `MemberImportVisibility` и пропустила ошибку. Повторная проверка всех исходников macOS и iOS с `-enable-upcoming-feature MemberImportVisibility` завершилась успешно для обоих клиентов.


Визуальная сверка Mac выполнена только с `09-widget-01…11.jpg` Grok Bot (S009–S019). Старый скриншот Blot не использовался. Полного совпадения пока нет.
