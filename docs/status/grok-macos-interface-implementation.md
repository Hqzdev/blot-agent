## Совместимость Swift core

- В `TaskResult` добавлены необязательные `additions`/`deletions`; старые payload декодируются без них. Статистика сбрасывается после последующей записи файла, пока не появится новый успешный diff. Для binary/неизвестного diff цифры не придумываются.
- Выбор cookies передаёт отдельное действие `allow_domains` с JSON-списком. Подмножество проверяется на пустоту, повторы и выход за подготовленные домены. Executor копирует только выбранные сайты. Старый executor, понимающий только `allow`, отклонит новый вариант, а не скопирует весь список; старый `allow` остаётся разрешением полного показанного списка.
- Закрытие вопроса сохраняет `dismiss` без значения; текущий `conversation_ask` возвращает состояние `dismissed` и null вместо ответа. Это не удаляет историю.
- Генерируемые v3 DTO, Java backend и web billing в этом проходе не менялись. Изменения относятся к Apple-local Swift core и представлению macOS; устройство iPhone не запускалось.

## Проверка

Полная Debug-сборка и запуск выполняются через `./script/build_and_run.sh --verify` на физическом Mac, с существующим `.build/xcode`. В начале и в конце проверки свободно более 30 ГиБ. Симуляторы не использовались.

7 Swift runtime-тестов прошли: сохранение всех 11 типов, повторные ответы, истечение срока, синхронизация/авторство, запрет секретов в ответе, ограничение доменов, legacy payload и diff, закрытие вопроса. Для визуальной проверки `bash scripts/check-conversation-card-ui.sh` подключается к уже собранному `Blot.debug.dylib` с `MemberImportVisibility` и запускает нативные NSHostingView с изолированными данными. Проверяются явный Reply против технической связи, группировка времени и все шесть состояний; сохраняются отдельные карточки и полные экраны.

В живом приложении проверены поиск и восстановление списка, переключение группы/личного чата, ввод/очистка черновика и смена кнопки отправки, раскрытие и закрытие браузера, настоящая миниатюра загруженного Example Domain. Тестовая вкладка закрыта, текст не отправлялся. Локальная галерея не загрузилась внутри WKWebView, поэтому проверка успешного preview выполнена на общедоступном Example Domain. Ошибка загрузки также остаётся настоящим состоянием, а не подменяется картинкой. Mail/Slack/платёж/запись ключа/копирование настоящих cookies при этой проверке не выполнялись.

Артефакты: `.build/grok-interface/launch.log`, `card-tests.log`, `render.log`, `screenshots/`; полные изолированные экраны — `.build/grok-chat-cards/screenshots/cards/shells/`. Живые снимки содержат историю пользователя и не публикуются. Актуальные количества кадров и результаты находятся в `.build/grok-interface/validation.json`.


Итог: 30 полных экранов + 22 отдельные карточки, обе темы; полный отчёт — [.build/grok-interface/report.html](../../.build/grok-interface/report.html). Дополнительно на последней сборке проверены сворачивание/возврат sidebar, корректная подпись группы и финальное открытое окно приложения.
