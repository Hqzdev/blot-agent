# Выбранная вкладка и размер браузера

Исправления от 9 ноября 2026 применены в текущем проекте `mac/workspace` поверх первой реализации браузера.

## Чтение открытого сайта

В первой версии агент мог работать со вкладками, созданными его собственным вызовом `browser_open`. Открытая владельцем вкладка имела другую область доступа, а инструменты не сообщали, какая вкладка выбрана. В групповом режиме обычного разговора дополнительно отключались все инструменты.

Теперь `browser_snapshot` принимает необязательный `tab_id`: без него читает выбранную вкладку, включая открытую вручную. Существующие явные вызовы с `tab_id` совместимы. Для пользовательской вкладки разрешено только чтение снимка, только пока она выбрана, только для агента с локальным разрешением на её origin. В результат добавлен `read_only_user_tab`. Смена выбранной вкладки между подготовкой и исполнением отклоняет устаревший вызов. Запись, навигация назад, закрытие и получение скриншота пользовательской вкладки через эту новую ветвь доступа не разрешаются. Изоляция чужих вкладок агента сохранена. Значения полей и cookies не передаются.

Контекст ответа сообщает о наличии вкладки, без её URL или содержимого. Он направляет модель к `browser_snapshot`, когда инструмент доступен, либо к настройкам доступа, когда разрешения нет. В групповом режиме разговора для несоциального запроса может предоставляться только `browser_snapshot` из уже выданных агенту инструментов; остальные операции остаются выключенными. Приветствия по-прежнему не запускают работу.

Разрешение владелец выдаёт сам: браузер → меню ⋯ → «Доступ агентов» → «Добавить текущий сайт и агентов чата» → «Сохранить доступ». Кнопка только заполняет форму; без сохранения права не меняются. В группе выбираются её действующие агенты. Разрешение относится ко всему origin, как и раньше. Проверка не меняла разрешения личного аккаунта пользователя.

## Изменение ширины

На Mac между чатом и браузером появился разделитель шириной 8 точек. Он изменяет ширину браузера в пределах 300–1000 точек, дополнительно ограниченных шириной окна. Чату остаётся минимум 420 точек. При открытой панели минимальная ширина окна — 760 точек. Уменьшение окна снова ограничивает ширину панели; сохранённое значение не может вытеснить чат.

Положение запоминается локально после отпускания мыши. Во время движения используется состояние SwiftUI без записи UserDefaults на каждом событии. Маленький `NSViewRepresentable` отвечает за курсор и захват мыши при пересечении WKWebView; состояние размера и ограничения принадлежат SwiftUI. Есть увеличение/уменьшение через Accessibility. Закрытие панели возвращает обычную компоновку чата.

## Проверка

- 160 тестов Swift-ядра и 18 тестов Apple-интеграций прошли.
- Настоящий WebKit на физическом Mac: выбранная ручная вкладка читается; другие origin, запись и устаревшая выбранная вкладка отклоняются. Проверены оба полных пути `LocalWorkspaceService`: личный чат и группа с решением маршрутизатора `conversation`. Без прав модель-фикстура получает отсутствие инструмента и объясняет доступ; после выдачи тестового разрешения получает реальный DOM выбранной страницы без открытия дополнительной вкладки. Внешняя LLM и личные сайты для проверки не использовались.
- Проверены крайние размеры панели, некорректное сохранённое значение и ширины окна 760–2560 точек. В изолированном окне с production-компонентом вручную через UI проверены перетаскивание в обе стороны, ограничения 300/852 при ширине 1280 и обратное движение после ограничения; чат остаётся видимым.
- Прошли существующие регрессии групп, задач и MCP. Финальные Mac и generic physical-device iOS сборки успешны; симуляторы не использовались. Сеанс Blot, запущенный пользователем из Xcode, не перезапускался. Для работы исправлений нужно запустить новую сборку. Работа на физическом iPhone в этом исправлении не проверялась.

Свободное место оставалось выше 20 GiB. Переиспользуются `.build/xcode`, `.build/ios` и существующие SwiftPM-каталоги. Одноразовые стенды браузера и MCP после проверки удаляются; исходное состояние перед правками и краткие результаты сохранены.

Существующая ветка `mac/embedded-browser` продолжена отдельным патчем `docs/patches/browser-selected-tab-and-resize.patch`. Он применяется после `embedded-browser.patch` и не включает посторонние локальные изменения. `origin/mac/main` (`f9f1ca7`) пока не содержит предшествующие зависимости; поэтому ветка остаётся набором сфокусированных патчей и отчётов, а рабочая реализация находится в текущем проекте.
