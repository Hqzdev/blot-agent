# Подключение MCP серверов к Blot

Дата: 1 ноября 2026. Статус: целевой контракт основной поставки. Настройки и операции ниже должны быть реализованы и пройти приёмку; этот документ сам по себе не означает наличия работающего MCP-клиента в текущей сборке.

Blot подключает инструменты внешних разработчиков через стандартный Model Context Protocol. Разработчик создаёт MCP-сервер, пользователь добавляет его в Blot и выдаёт права выбранным агентам. Собственный несовместимый вариант MCP и обязательная публикация в магазине Blot не требуются.

## Транспорт и версия

Локальный сервер работает на компьютере пользователя через stdio. Удалённый сервер использует Streamable HTTP и HTTPS для сетевого доступа. Оба варианта определены в [официальной спецификации транспорта](https://modelcontextprotocol.io/specification/latest/basic/transports).

Первый проверочный профиль ориентируется на совместимость с версией 2025-11-25: инициализация, согласование capabilities, обнаружение `tools/list` и вызов `tools/call`. Более новые версии добавляются только после проверки соответствующего SDK и различий протокола; клиент не посылает старые сообщения под номером новой версии. Поддержанные версии публикуются рядом с номером релиза Blot. Семантика инструментов этого профиля описана в [MCP tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools).

Для stdio stdout содержит только сообщения протокола, диагностический текст направляется в stderr. Команда запуска и аргументы задаются отдельно, без скрытого shell-скрипта. Рабочая папка, разрешённые переменные среды, таймаут и способ завершения задаются явно.

## Подключение пользователем

1. Открыть на ПК «Подключения → MCP → Добавить сервер».
2. Выбрать stdio или HTTP, задать имя подключения и параметры.
3. Секретные значения внести в защищённые поля; они не появляются в обычном экспорте конфигурации.
4. Выполнить проверку соединения и инициализацию.
5. Просмотреть обнаруженные инструменты и выбрать разрешённые для подключения.
6. Выдать агентам доступ к нужным инструментам и областям.
7. Запустить пробную задачу и проверить реальный результат в журнале.

Телефон может просматривать подключение и отвечать на запросы разрешений. Он не запускает локальный MCP-процесс вместо ПК. Подключение принадлежит workspace и не переносится на другой компьютер автоматически.

## Описание инструмента

Инструмент должен иметь стабильное имя, понятное назначение, входную JSON Schema и проверяемый результат. Входные данные валидирует сам сервер; инструкция модели не заменяет эту проверку.

Ниже самостоятельный пример описания инструмента чтения доступности услуги. Это описание в ответе discovery, а не полный runnable MCP-сервер:

```json
{
  "name": "lookup_service_availability",
  "description": "Возвращает доступные интервалы выбранной услуги на указанную дату без создания записи.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "serviceId": { "type": "string", "minLength": 1 },
      "date": { "type": "string", "format": "date" },
      "timeZone": { "type": "string", "minLength": 1 }
    },
    "required": ["serviceId", "date", "timeZone"],
    "additionalProperties": false
  }
}
```

Рекомендуется разделять чтение доступности и создание бронирования на разные инструменты. Для создания внешней записи возвращаются подтверждённый внешний ID и фактические параметры; отсутствие свободного времени — нормальный бизнес-результат. Таймаут после отправки записи не выдаётся за гарантированное отсутствие бронирования.

## Разрешения и доверие

Метаданные сервера помогают описать действие, но не являются доказательством его безопасности. Blot применяет свою политику по умолчанию и позволяет владельцу настроить её. Новый неизвестный инструмент не получает автоматически права записи или доступа ко всем источникам.

Проверки выполняются перед вызовом: разрешён ли сервер, инструмент, агент, компьютер, область и бюджет; не отменена ли задача; актуальна ли схема и карточка подтверждения. Разрешение человеку показывается до передачи побочного действия серверу. Смена существенных аргументов требует повторного подтверждения.

Процесс stdio не становится изолированным только из-за протокола MCP. Доверенный локальный сервер может иметь доступ своего пользователя к системе. Для недоверенного кода требуется отдельная подготовленная среда с ограниченными файловыми и сетевыми возможностями; иначе пользователь видит предупреждение об уровне доверия при добавлении, а Blot не обещает защиту от произвольного поведения бинарника.

Ответ инструмента не может назначить агенту новую роль, отключить подтверждения или потребовать выдачи секрета. Инструкции такого рода сохраняются как недоверенное содержимое источника. Секреты не включаются в обычный контекст модели.

## Авторизация

Удалённое подключение использует поддержанный сервером OAuth-процесс или явно настроенный credential. Клиент проверяет адрес сервера, issuer и аудиторию токена там, где применяется OAuth; credentials одного сервера не пересылаются произвольному другому серверу. Параметры авторизации сверяются с согласованной версией протокола и [официальным разделом authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization).

Локальные секреты выдаются процессу адресно через разрешённые переменные среды или другой поддержанный защищённый механизм. В сервер не передаётся полное окружение Blot. При отзыве подключения прекращаются новые вызовы и очищаются связанные credentials в пределах выбранного действия пользователя.

## Результаты и ошибки

Результат должен позволять различить данные, бизнес-отказ, ошибку инструмента и неопределённый исход внешнего изменения. Для источников полезны ID, URL, время получения и версия. Большие результаты ограничиваются или отдаются частями; бинарные данные не маскируются под огромную текстовую строку.

При сетевой ошибке Blot может повторить безопасное чтение в пределах политики. Запись повторяется только при доказанной идемпотентности или установленном фактическом исходе. Если внешний API поддерживает idempotency key, разработчик использует его и сохраняет связь с операцией. Blot command ID сам по себе не создаёт идемпотентность в чужом сервисе.

Журнал показывает имя сервера, инструмент, безопасную сводку аргументов, длительность, состояние и результат. Пароли, OAuth-токены, полные заголовки авторизации и приватное содержимое диагностических логов не публикуются.

## API управления Blot

Целевой API управления содержит операции добавить/изменить/проверить/отключить подключение, обновить discovery, перечислить инструменты, выдать и отозвать доступ агента. Это часть аутентифицированного workspace API, а не второй протокол вызова инструментов вместо MCP.

Локальное подключение содержит connection ID, workspace ID, транспорт, имя, ссылку на credential, allowlist инструментов, таймауты и версию конфигурации. Секретные значения не возвращаются в GET. При изменении исполняемой команды или адреса повторяется подтверждение доверия. Точные HTTP-маршруты и DTO фиксируются в обновлённом OpenAPI до реализации; существующие маршруты v2 не считаются уже поддерживающими эти операции.

## Проверка совместимости

| Сценарий | Ожидаемый результат |
| --- | --- |
| Подключить локальный и удалённый сервер | Инициализация и список инструментов без изменения кода Blot |
| Передать неверный аргумент | Ошибка валидации с понятным сообщением |
| Выполнить инструмент чтения | Реальные данные и журнал вызова |
| Отказаться от записи | Внешний побочный эффект отсутствует |
| Подтвердить запись | Одно действие с установленным внешним итогом |
| Изменить схему/адрес/команду | Нет наследования неподходящих разрешений |
| Прервать соединение во время записи | Нет слепого дублирования; неопределённость видна |
| Отозвать инструмент или сервер | Новые вызовы запрещены, активные корректно завершаются/отменяются |
| Прислать инструкцию повысить права | Содержимое не меняет политику Blot |

Приложение считается совместимым после подключения независимого тестового MCP-сервера по этой инструкции. Встроенная фикстура без реального транспорта этого не подтверждает.
