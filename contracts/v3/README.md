# Контракты Blot v3

Ноябрьские модели и граница будущего API для всех клиентов. Это спецификация, а не реализованные HTTP-маршруты.

- `model.json` — единый источник 36 публичных записей и 3 value objects; дополнения Apple v1 описаны в [плане](../../backend/plans/apple-v1/contracts.md).
- `entities.schema.json` — JSON Schema 2020-12, `openapi.json` — OpenAPI 3.1.
- `command.schema.json` — команды, `event.schema.json` — уведомления об изменении записи.
- `../../fixtures/v3/` — общие примеры Java/Swift и каталог состояний; `presentation.json` — только для предпросмотра.
- `../../scripts/generate-v3-contracts.py` обновляет DTO, схему сущностей и примеры из `model.json`; затем `python3 scripts/format-v3-java.py` применяет форматирование только к исходникам v3.

Аккаунты, доверие и квоты принадлежат облаку; история, память, файлы и workspace — устройствам. DTO аккаунта не содержит пароля или его хеша. Секреты, refresh tokens и pairing secrets не входят в общие списки и события. Public key и краткоживущий код сверки секретами входа не являются.

Workspace — общее пространство данных Apple-клиентов. Nullable executorDeviceId сохранён для чтения прежних fixtures и не задаёт полномочия; исполнитель определяется задачей и lease generation. Project — проект внутри него. Task в v3 — всё поручение пользователя; октябрьский Run соответствует Task, октябрьский Task — шаг плана. Типизированные состояния v3 изолированы в `BlotV3` / `dev.blot.core.v3`. Код работающего v2 пока сохранён отдельно; преобразование неоднозначных WAITING/REVIEWING в новые состояния не выполняется автоматически.

Новая версия не поддерживает старые клиенты и миграцию тестовой истории. При реализации хранения v3 создаётся отдельная база; удаление прежней истории не производится этим блоком. Клиент не отправляет владельца или тип устройства как доверенный факт. Executor из команды — запрошенный выбор; ядро обязано проверить его относительно authenticated device. Origin и owner определяются сервером.

Принятие команды не означает успешного исполнения. Данные, receipt и outbox фиксируются вместе. Повтор commandId с тем же содержимым возвращает квитанцию, с другим — конфликт. UNKNOWN требует сверки; внешнее действие автоматически не повторяется. Событие несёт ID/версию записи, клиент перечитывает подтверждённые данные. Snapshot должен быть согласован с sequence. Пагинация: до 100 записей по умолчанию, до 500; cursor непрозрачен для клиента. Heartbeat SSE — 15 секунд, разрыв без события — переподключение через 45 секунд; исходящая HTTP-команда — 30 секунд. Эти требования реализуются следующим блоком API.

Отдельная проверка BLOT-06 (запрет ПК → другой ПК), реальное шифрование канала и все сквозные сценарии остаются открытыми.

Локальное ядро `BlotWorkspace` реализует SQLite, команды чата и durable stream recorder. HTTP/relay/account/lease ещё не реализованы для Apple v3. `--workspace-local` включает отдельную базу без импорта demo/v2; обычный запуск пока остаётся demo.

Последнее дополнение Apple MVP: `ModelStep`, `ExecutionMode` и `ModelStepState` фиксируют запрос/результаты/usage и локальное владение выполнением. Уточнение пользователя: native peer-sync Wi-Fi/Bluetooth вместо обязательного cloud relay; вход через сайт. [Фактический срез](../../backend/plans/apple-v1/mvp-completion-2026-11-04.md) имеет приоритет над историческим описанием demo/gateway выше.
