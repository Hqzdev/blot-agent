# Blot Windows

JavaFX-клиент серверного v3 runtime. Использована отдельная копия локальной заготовки; исходная незакоммиченная папка сохранена. Старый JavaFX Gradle plugin был несовместим с Gradle 9 и Java 25, поэтому JavaFX подключён обычными Maven-зависимостями для Windows. Gradle wrapper совпадает с проверенным backend wrapper 9.1.

Общие JSON/HTTP-клиент и generated DTO подключаются непосредственно из `backend/client` и `backend/core/src/main/java/dev/blot/core/v3`. Общие fixtures и каталог состояний тестируются перед сборкой дистрибутива. Swift-пакеты приложением не исполняются.

## Сборка и запуск

Нужен JDK 25; задайте JAVA_HOME локально.

```powershell
cd apps/windows/Blot
./gradlew.bat --no-daemon test installDist
./build/install/Blot/bin/Blot.bat
```

Это installDist для установленной Java, а не подписанный Windows installer со встроенным JRE.

## Подключение

Для backend на этом компьютере можно указать HTTP loopback; удалённый сервер требует HTTPS с доверенным сертификатом и сессию устройства. Введите адрес сервера и bearer-сессию в приложении. Токен хранится только в памяти, не записывается в URL или настройки и не пересылается через HTTP redirect.

Создайте агента с именем, инструкциями и поддерживаемой сервером моделью, затем создайте личный чат. Ответ модели появляется после подтверждения сервером; статусы ожидания, ошибки и прерывания не обозначаются как успешный ответ. Snapshot обновляется раз в две секунды. При неопределённой отправке повторяется прежняя команда с тем же идентификатором и содержимым, а не создаётся новая.

[Граница серверного runtime](../../docs/architecture/v3-server-runtime.md): личный текстовый чат реализован; группы, инструменты, вложения, расписания и задачи не перенесены из Swift и явно отклоняются сервером. Существующие данные v2 не преобразуются автоматически.
