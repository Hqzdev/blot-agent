## Принятые решения

- На Mac и iPhone собственная SQLite-база v3, локальные вложения и очередь исходящих изменений. Устройства выполняют переносимые задачи самостоятельно; модели и Google требуют интернет.
- Workspace — общее пространство данных аккаунта, device — конкретная установка. Workspace не является владельцем выполнения. `Task.execution.executorDeviceId` выбирается явно; lease ограничивает одного активного исполнителя и имеет монотонное поколение. История другого устройства не даёт право исполнять его задачу.
- `packages/BlotWorkspace` — общий Swift-пакет без SwiftUI. Отдельные SRP-компоненты хранения, команд, записи потока, репликации, разрешений, оркестрации и адаптеров. Зависимости передаются через инициализаторы; композиция вместо наследования.
- `BlotDomain` содержит генерируемые wire-модели. SwiftUI наблюдает модели представления; общий адаптер приложения переводит команды/изменения в snapshot. Keychain, уведомления, жизненный цикл и разрешённые файлы остаются платформенными адаптерами.
- Java/Spring остаётся сервером аккаунтов, сессий, доверия, encrypted relay, GigaChat gateway/квот и lease. В iOS JVM не поставляется. Старый Java-цикл не получает новые Apple-задачи; отделение очередей обязательно до включения рабочего режима.
- Сервер хранит только зашифрованные изменения/вложения, метаданные доставки и необходимые account/lease/quota данные. Неподтверждённые данные relay живут 30 дней. ACK принимается после локального commit; пропуск журнала требует согласованного snapshot от доверенного устройства.
- Первые модели: встроенный GigaChat через серверный шлюз и OpenAI-совместимый API с личным ключом. Первые реальные сервисы: Gmail и Google Calendar. Google OAuth и токены отдельные на каждом устройстве; статус подключения указывает deviceID.
- Точный digest связывает подготовленное действие с разрешением. `UNKNOWN` означает сверку; повтор отправки письма не запускается автоматически.
- Демо остаётся отдельным режимом, без внешних операций. SQLite v3 не читает и не перезаписывает JSON демо или v2 DB. Импорт — отдельная операция с резервной копией и ID mapping; демо-Google объекты не становятся реальными.

## Начальное состояние репозитория

Оба entrypoint вызывают `WorkspaceBootstrap.makeStore()`. Обычный старт сейчас выбирает `.demo`: Mac использует `MacDemoWorkspace`, iOS — `WorkspaceDemoData`, изменения сохраняются платформенными JSON-сервисами. `UnavailableWorkspaceService` явно отказывает v3; `PreviewWorkspaceService` меняет тестовый snapshot. Октябрьский Java API и агентный цикл существуют отдельно и не являются готовым Apple v3 API. Генератор DTO и общие fixtures уже были, но отсутствовали группы, версии навыков и репликация.

Первая поставленная основа: дополнение wire-моделей, SQLite с транзакционным outbox/receipt/FTS, локальные команды чата, запись и восстановление частичного ответа, OpenAI-compatible SSE transport и Keychain-адаптер, подключение обоих Xcode targets к отдельному local mode. Это компонентный прогресс, не 70% продукта. Детали фактических проверок — в acceptance.

## Как открыть текущий локальный срез

После сборки передать приложению `--workspace-local` в launch arguments (на Mac также `open -n .build/xcode/Build/Products/Debug/Blot.app --args --workspace-local`). Оба target используют одну библиотеку, но собственные файлы `Application Support/Blot/WorkspaceV3/workspace-v3.sqlite` в контейнере установки. Этот флаг не создаёт cloud account и не соединяет устройства; обычный старт остаётся demo.

В Settings → AI models → Compatible API указать полный HTTPS endpoint Chat Completions, model ID и личный ключ. Настройки сохраняются в локальном Keychain с `ThisDeviceOnly`. Сохранение проверяет формат конфигурации, но не заявляет проверенную capability или успешную авторизацию. Первый настоящий запрос проверяет доступность сервиса. Текущий транспорт — текстовый stream, без tools/images/usage accounting; его формат соответствует [Chat Completions API](https://developers.openai.com/api/reference/resources/chat).

Создание/отправка, ответ на сообщение, переименование, pin/archive/delete и восстановление истории работают через общее ядро. Если ключа/сети нет, сообщение остаётся локально, ошибка видна. «Повторить ответ» в меню исходного пользовательского сообщения создаёт новую явную попытку без нового user message. Остановка/обрыв сохраняют terminal status частичного ответа. Неподключённые команды не должны выдавать успешный внешний результат.

Расширение основы: локальные агенты с неизменяемыми revisions, группы/участники, реакции/прочтение, память/кандидаты/инвалидация резюме, навыки/параметры, выбранные файлы и экспорт, расчёт расписаний/очередь задач/бюджеты. Конфликты инструкций/расписаний сохраняют версии и требуют явного выбора; новые задачи ждут согласования. Разрешения связаны с проверяемым digest точной подготовки, а начатые вызовы после сбоя восстанавливаются как UNKNOWN.

Отдельный `backend/cloud` реализует account/session/device/relay/lease и текстовый GigaChat gateway с квотами. Проверен настоящий Swift CryptoKit → HTTP → Java JCE → вторая SQLite путь с раздельными изменениями; это интеграционный harness с временными test identities. Три установки проходят native bootstrap, подтверждённую подписью цепочку сопряжений, ECDH-передачу ключей, отзыв третьего устройства, новый epoch и многоблочные зашифрованные вложения. Сессия не восстанавливает credentials после конкурентного выхода. Это не заменяет регистрацию/QR UI, физическую приёмку приложений Mac+iPhone. Текущий `--workspace-local` остаётся локальным и не подключается к серверу автоматически.

Рабочий Swift tool loop/координатор, реальный GigaChat, account/pairing UI и подключение sync/file services к приложениям, Google REST-инструменты, системный фон и полная data lifecycle приёмка ещё требуют реализации/проверки. Google client IDs пока не зарегистрированы: подготовлены [конфигурация, скрипт и инструкция регистрации](google-oauth.md), PKCE/state и token exchange/refresh. [Cloud configuration и HTTP API](cloud.md) описывают отдельный процесс, секреты и профиль развёртывания; публичное окружение ещё не развёрнуто.

Общее ядро проверено на физическом iPhone в отдельном подписанном host: 35 проверок, включая настоящий Keychain. Это компонентная проверка; приложения с реальными моделью и Google на Mac+iPhone пока не приняты. Точные результаты и границы — в [acceptance.md](acceptance.md).

Машинный отчёт текущего среза: [verification-2026-11-04.json](verification-2026-11-04.json); исходные журналы и подробный SHA-256 manifest остаются в `.build/`. Сетевая передача snapshot также реализована и проверена: ожидание донора, подписанный manifest, многоблочная загрузка с возобновлением, сохранение локальных изменений и последующие события. Следующий незакрытый шаг — композиция account/pairing/sync/snapshot в интерфейсах; после него рабочий Swift tool loop и реальные интеграции.
