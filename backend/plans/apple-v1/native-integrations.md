# План MVP: системный календарь и приложения Apple

Дата: 4 ноября 2026. Статус: **план, реализация и приёмка не выполнены**.

По уточнению пользователя системные интеграции становятся основным путём MVP. Gmail REST и Google Calendar REST откладываются. Вход в аккаунт Blot через сайт, включая возможный Google Sign-In, остаётся отдельной подсистемой: это не разрешение на доступ к почте или календарю.

## 1. Результат и границы

На Mac и iPhone пользователь входит в Blot, включает системную интеграцию в настройках, выдаёт разрешение ОС и обращается к агенту обычным сообщением. Агент читает выбранные календари, предлагает время, готовит событие или напоминание, показывает точные параметры и выполняет подтверждённое действие. Подготовленный документ или письмо можно передать выбранному приложению.

Первый вертикальный сценарий: «Найди завтра свободные полчаса для встречи» → чтение разрешённых календарей → предложение → выбор времени и подтверждение → сохранение в выбранный календарь → проверка результата в системном Calendar → перезапуск Blot без повторного создания. Оба устройства проходят его независимо.

| Возможность | iPhone | Mac | Граница MVP |
| --- | --- | --- | --- |
| Календарь: список, поиск, чтение, сводка | EventKit | EventKit | Только доступные на этом устройстве и выбранные пользователем календари |
| Поиск свободного времени | Расчёт по полученным событиям | То же | Нет сведений о занятости произвольных приглашённых |
| Создание, изменение и удаление события | EventKit, точное подтверждение Blot | То же | Учитываются права календаря и выбранный экземпляр повторения |
| Напоминания: списки, создание, изменение, завершение, удаление | EventKit | EventKit | Отдельное разрешение на Reminders |
| Файлы и документы | Выбор файлов, экспорт, системная передача | Выбор файлов, экспорт, открытие выбранным приложением | Только выбранные файлы; экспортируемые форматы уже поддержанного ядра |
| Подготовленное письмо | Системное окно отправки, если доступно | Системный share/compose-путь выбранного почтового приложения | Финальную отправку выполняет пользователь; чтение ящика не входит |
| Открыть приложение или ссылку | Поддерживаемая ссылка/URL scheme | Проверенный bundle ID/ссылка через NSWorkspace | Успешное открытие не означает выполнение действия внутри приложения |
| Запустить выбранную «Команду» | Системный Shortcuts URL, при необходимости переход в приложение | Такой же путь | Пользователь заранее сохраняет и выбирает команду; фоновое выполнение не гарантируется |
| Вызвать Blot из «Команд» | Тонкие App Intents Blot | То же | Три действия: открыть чат, подготовить поручение, показать подготовленное действие |

Календарь Google, Exchange или iCloud, уже добавленный в ОС и доступный EventKit, используется как системный источник. Blot не запрашивает его Google OAuth. Добавление аккаунта и синхронизация с провайдером остаются настройками ОС.

Не включать в этот блок: произвольное управление интерфейсами, Accessibility-автоматизацию, Terminal/AppleScript, чтение чужих контейнеров, универсальный список всех приложений на iOS, чтение Apple Notes или почтовых ящиков без отдельного поддерживаемого API. Для Notes в MVP — передача текста/файла через системное меню либо выбранную пользователем команду.

## 2. Ограничения, которые определяют реализацию

- Для чтения и изменения существующих событий нужен полный доступ EventKit. Уровень write-only не подходит для поиска свободного времени и сверки результата. Запрашивать доступ после явного выбора функции, а отказ обрабатывать без повторного системного запроса при каждом открытии. Источник: [Accessing the event store](https://developer.apple.com/documentation/eventkit/accessing-the-event-store).
- ОС выдаёт полный доступ к событиям, а выбор отдельных календарей в Blot ограничивает использование данных самим приложением. Интерфейс должен различать эти два уровня. В контекст модели передаётся только необходимая выборка по разрешённым в Blot источникам и периоду.
- `EKCalendarItem.attendees` доступен только для чтения. Добавление приглашённых и серверная рассылка приглашений не входят в прямой адаптер EventKit. Если задача требует участников, предложить ручное завершение в подходящем приложении; не сообщать об отправленном приглашении. Источник: [attendees](https://developer.apple.com/documentation/eventkit/ekcalendaritem/attendees).
- EventKit ID не является общим стабильным ID двух устройств; даже перенос события между календарями может изменить `eventIdentifier`. Хранить привязку по устройству и подтверждать найденный объект. Источник: [eventIdentifier](https://developer.apple.com/documentation/eventkit/ekevent/eventidentifier).
- App Intents публикует действия самого Blot для системы. Для действий другого приложения используем его документированные ссылки или пользовательский Shortcut; не предполагаем универсальный прямой вызов любого чужого intent. Источники: [Creating your first app intent](https://developer.apple.com/documentation/appintents/creating-your-first-app-intent), [Shortcuts URL scheme — iPhone](https://support.apple.com/en-ie/guide/shortcuts/apd624386f42/ios), [Mac](https://support.apple.com/en-nz/guide/shortcuts-mac/apd624386f42/9.0/mac/26).
- Запуск Shortcut не доказывает, что внешнее действие завершено. Команду пользователь может изменить после подключения; Blot не гарантирует неизменность её содержимого и собственное подтверждение описывает только имя и передаваемый ввод. Команды с непрозрачными побочными эффектами требуют пользовательского запуска каждого вызова, без постоянного автоматического разрешения.
- Системное окно письма/передачи не даёт Blot доступ к содержимому ящика или доказательство доставки. Открытие, отмена, передача и подтверждённое API-завершение отражаются раздельно. Источник для iOS: [MFMailComposeViewController](https://developer.apple.com/documentation/messageui/mfmailcomposeviewcontroller).

## 3. Архитектура и ответственность

Использовать уже существующие `WorkspaceToolRegistry`, `WorkspaceToolExecuting`, `WorkspacePermissionService`, `PreparedAction`, `ToolInvocation` и сохранённые шаги модели. Не создавать второй агентный цикл или отдельную систему разрешений.

Предлагаемая структура:

| Часть | Ответственность |
| --- | --- |
| `packages/BlotWorkspace` | DTO операций, схемы аргументов инструментов, подготовка действий, digest, состояние выполнения, сверка и журнал |
| Новый `packages/BlotAppleIntegrations` | Адаптер EventKit и платформенные реализации разрешений, файлов, открытия, compose и Shortcuts; зависит от интерфейсов ядра |
| Composition root обоих приложений | Создание адаптеров и явная передача зависимостей в реестр инструментов |
| SwiftUI обоих приложений | Подключение источников, выбор календарей, просмотр результатов, подтверждение и переход в системный интерфейс |
| Отдельный слой App Intents | Тонкая маршрутизация в сервисы Blot без дублирования бизнес-логики |

В новом пакете выделить отдельные протоколы CalendarRepository, ReminderRepository, SystemAccessProvider, DocumentHandoff, MailComposer, ApplicationLauncher и ShortcutRunner. Названия окончательно закрепляются при реализации. EventKit-объекты не выходят наружу адаптера; ядро получает Sendable-снимки. Доступ к `EKEventStore` сериализован; приложение повторно читает объекты после уведомления об изменении.

Набор доступных инструментов определяется одновременно платформой, текущими разрешениями ОС, выбором источников пользователем и настройками агента. Модель не выбирает произвольный bundle ID, URL scheme или имя команды вне зарегистрированного каталога.

## 4. Данные, команды и состояния

Сначала расширить `contracts/v3/model.json` и общие fixtures, затем запускать генератор Swift/Java. Поля и сущности ниже — проектируемый контракт, не готовые DTO.

- **SystemConnection:** provider (`systemCalendar`, `systemReminders`, `systemApplications`, `systemShortcuts`), workspace, device, поддерживаемые операции. Фактические разрешения ОС, список выбранных локальных календарей, имена команд и file bookmarks хранятся локально. На другом устройстве подключение не считается доступным автоматически.
- **ExternalObjectReference:** собственный record ID Blot, device ID, provider, local calendar/item locator, occurrence, необязательные внешние подсказки и fingerprint прочитанных полей. Не считать EventKit locator идентификатором объекта на другом устройстве.
- **PreparedSystemAction:** command ID, task ID, executor device ID, provider, тип операции, точные аргументы, fingerprint исходного объекта, digest, срок подтверждения. Для календаря: название, календарь, начало/конец, IANA timezone, all-day, повторение и область изменения серии. Для передачи: приложение, текст, адресаты и hashes вложений, если они доступны этому пути.
- **SystemInvocation:** invocation ID, command ID, подготовленная версия, попытка, статус, сохранённая внешняя привязка, результат сверки. Состояния описывают факты: `PREPARED`, `AWAITING_APPROVAL`, `AWAITING_USER`, `RUNNING`, `HANDED_OFF`, `SUCCEEDED`, `CANCELLED`, `FAILED`, `UNKNOWN`. Переходы и миграция согласуются с существующей state machine до добавления новых enum-значений.

Первые инструменты: `system.calendar.list`, `events`, `free_slots`, `prepare`, `execute`, `reconcile`; `system.reminders.list`, `prepare`, `execute`, `reconcile`; `system.documents.share`; `system.mail.compose`; `system.apps.open`; `system.shortcuts.run`. Конкретные имена полностью перечисляются в схемах, без динамического построения команды из ответа модели.

Любое изменение аргументов отменяет старое подтверждение. Перед записью повторно проверяются разрешение ОС, исполнитель, отмена задачи, права календаря, срок grant и исходный fingerprint. Изменение события вне Blot требует новой подготовки. EventKit не предоставляет используемого здесь серверного etag/CAS: повторное чтение уменьшает окно конфликта, но не даёт атомарной защиты от внешнего редактирования. Приёмка должна зафиксировать эту границу, а не обещать строгую изоляцию.

## 5. Восстановление и синхронизация

1. Сохранить `PREPARED` и точное подтверждение до обращения к ОС; сохранить invocation до первой попытки записи.
2. После EventKit save немедленно сохранить local locator, нормализованный снимок и факт **локального** сохранения. Успех не означает доставку события в iCloud/Exchange/Google или на другое устройство.
3. Для созданных Blot событий использовать operation UUID в поддерживаемом поле, предварительно проверив его сохранение нужными провайдерами; маркер в `event.url` возможен только если не вытесняет пользовательскую ссылку. Локальный журнал обязателен в любом случае. При невозможности надёжной маркировки сверка остаётся ограниченной.
4. При аварии между записью EventKit и фиксацией результата — `UNKNOWN`. Сначала поиск по сохранённой привязке/маркеру и ограниченному диапазону, проверка совпадения. Ноль либо несколько недоказуемых совпадений не разрешают автоматическое повторное создание; требуется решение пользователя.
5. Для изменений сравнить ожидаемый итог с повторно прочитанным объектом. Для удаления отсутствие объекта учитывается вместе с журналом и целевой привязкой; само по себе оно не доказывает авторство удаления. Не менять похожий объект вместо потерянной привязки.
6. Передача документа, открытие compose или запуск Shortcut дают `HANDED_OFF`/`AWAITING_USER`, если нет достоверного подтверждения результата. Нет callback → нет автоматического повторного запуска.
7. Blot синхронизирует поручение и результат через принятый peer sync. Сами календари синхронизирует ОС. Получение истории на втором устройстве не повторяет системное действие. Офлайн локальный Calendar доступен в пределах данных ОС; подключение GigaChat по-прежнему требует интернет.
8. Расписание закреплено за устройством. Чтение или подготовка выполняются при доступном исполнителе; подтверждение записи и интерфейс передачи ждут пользователя в приложении. Закрытый iPhone не обязан запустить стороннюю программу в заданную минуту.

## 6. Порядок реализации и gates

| Этап | Задачи | Выход / зависимость |
| --- | --- | --- |
| N0 — зафиксировать контракт | Версия реестра, схемы инструментов, native capabilities, новые snapshots/fixtures и ошибки; отметить Google REST отложенным | Согласованные Java/Swift DTO и тесты переходов; до записи данных |
| N1 — разрешения и чтение | Новый пакет, EventKit adapter, usage descriptions/entitlements обоих targets; настройка «Системный календарь», выбор источников, обновление после изменения/возврата в приложение | Реальный список событий и сводка на Mac+iPhone с выключенным вторым устройством; отказ/отзыв не ломает чаты |
| N2 — полный календарный цикл | Свободные интервалы, подготовка/подтверждение, create/update/delete, read-only calendar, timezone/DST/all-day/recurrence, durable invocation и UNKNOWN reconciliation | Вертикальный сценарий из раздела 1; никаких дублей при перезапуске и повторе command ID |
| N3 — напоминания | Отдельное разрешение и выбор списков, prepare/approve/execute для создания, изменения, завершения и удаления | Реальный результат в Reminders на обеих платформах; отсутствие разрешения не отключает Calendar |
| N4 — документы, почта и открытие | Платформенные адаптеры share/open/compose, каталог проверенных приложений/ссылок, настройки агента и честные статусы передачи | Документ открывается; письмо можно проверить и отправить вручную; недоступное приложение даёт понятную ошибку |
| N5 — «Команды» и App Intents | Выбор пользовательских команд, параметризованный URL, корреляция callback без доверия к нему как доказательству внешнего эффекта; 3 тонких intents самого Blot | Проверка реальной простой команды; отмена/таймаут не становятся успехом; intent открывает точную задачу/чат |
| N6 — lifecycle и приёмка | Возврат из системного интерфейса, revocation, crash recovery, peer replay, расписания, физические прогоны и доказательства | Приняты N001–N012; затем пересчёт всего MVP по общему реестру |

N1 начинается после N0; N2 после N1; N3–N5 используют готовую систему действий N2. N6 проверяет композицию целиком. Готовность OAuth Google не блокирует этот блок. Публичная регистрация Blot, рабочий чат с GigaChat и основные агенты остаются отдельными обязательными gates общего MVP.

При конфигурации: `NSCalendarsFullAccessUsageDescription` и `NSRemindersFullAccessUsageDescription`; write-only usage description — только если реализован отдельный такой режим. Для sandboxed Mac — календарный entitlement. Проверить signing/entitlements обоих targets и инструкции на iOS/macOS 26, которые указаны текущим проектом. Добавлять Contacts usage description только при включении конкретного системного UI, который его требует; не запрашивать доступ к контактам заранее.

## 7. Проверяемый реестр блока

Исходные A001–A098 и матрица BLOT сохраняются. A053–A062 остаются историческими Google-сценариями и переводятся в отложенный объём; они не становятся принятыми от наличия EventKit. Добавляются 12 новых сценариев. Актуальная версия общего реестра: **110 сценариев; 70% требуют минимум 77 полных PASS**. Срез 0/98 остаётся историческим; новый реестр не создаёт принятых сценариев. Дополнительные Apple-интеграции не заменяют остальные функции приложения.

| ID | Сценарий и проверяемый результат | Начальное состояние |
| --- | --- | --- |
| N001 | Выдать, запретить и отозвать Calendar permission на Mac/iPhone; UI и доступные tools отражают актуальное состояние | NOT RUN |
| N002 | Выбрать календари, получить реальные события за ограниченный период и сводку с источниками; исключённые календари не читаются в контекст агента | NOT RUN |
| N003 | Найти свободное время с timezone/DST/all-day/повторениями; неполные источники помечены, занятость сторонних людей не выдумана | NOT RUN |
| N004 | Подтверждённое создание события независимо на обоих устройствах; точные параметры видны в Calendar после перезапуска | NOT RUN |
| N005 | Подтверждённое изменение и удаление; внешнее редактирование, read-only и удалённый календарь дают корректный конфликт/отказ | NOT RUN |
| N006 | Повтор command ID, crash до/после save, потерянная привязка и peer replay не создают дубль; неопределённость остаётся UNKNOWN | NOT RUN |
| N007 | Изменение одного экземпляра и доступной области серии, timezone/DST/all-day, права на приглашённое событие; неподдерживаемый запрос честно отклоняется | NOT RUN |
| N008 | Отдельные Reminders permission/списки; создать, изменить, завершить и удалить с подтверждением; результат сохранён в системном приложении | NOT RUN |
| N009 | Выбрать реальный файл, подготовить результат, экспортировать и открыть/передать его; отмена и недоступный файл не превращаются в успех | NOT RUN |
| N010 | Проверить адресатов/текст/вложения, открыть поддерживаемый системный compose; отмена/отсутствие аккаунта обработаны; доставка не заявляется по факту открытия | NOT RUN |
| N011 | Открыть выбранное приложение/поддерживаемую ссылку на обеих платформах; неизвестная цель отклонена; открытия недостаточно для статуса выполненного поручения | NOT RUN |
| N012 | Пользовательский Shortcut принимает согласованный ввод; отмена/таймаут/повтор обработаны; три App Intents Blot открывают правильный контекст | NOT RUN |

Для каждого PASS нужны build/revision, устройство/ОС, условия, шаги, наблюдаемый итог и артефакт. Тесты EventKit adapter/state machine выполняются отдельно от реального TCC и системного UI. Полноту N001–N012 подтверждают физические Mac+iPhone, а не только симулятор или mock.

В старой матрице BLOT-18 системное составление письма — лишь частичное покрытие, поиск почты не реализован. BLOT-19 EventKit — частичное покрытие исходного требования прямых Google/Яндекс подключений. Новые источники и ограничения отмечаются явно.

## 8. Что убрать из критического пути MVP

- Подключения Gmail/Google Calendar и Google scopes заменить в продуктовых настройках системными Calendar, Reminders, Files, Applications и Shortcuts, с доступностью по устройству. Google REST не объявлять работающим.
- При реализации убрать обязательность нативных Google client IDs из валидатора сборки, если выбран только системный набор. Существующие заделы OAuth не удалять вместе с чужими изменениями; отдельно проверить использования и удалить неиспользуемый код без потери входа через сайт.
- Не менять Google web client ID/secret и callback сайта как следствие этой замены: это другой OAuth-клиент и другой сценарий.
- Не добавлять серверный доступ к EventKit: операции выполняются локально на выбранном устройстве. Не требовать iCloud credentials или приватные API Apple.

Следующий шаг реализации: N0 → N1 → один подтверждённый create/readback из чата через N2, затем остальные системные действия.
